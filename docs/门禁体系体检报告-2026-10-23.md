## 3. 当前仍存的已知缺口（可执行建议）

### 3.1 产物未重建（阻塞项，需他人收尾）

- **现象**：`check_artifact_soak_fresh.ps1` 本地 **FAIL**（产物比 soak/A7 判定源码旧 12.6h）。
- **硬约束**（round 59 实测精确化）：① `dist/workbench.exe` 被活实例占用；② `go vet ./cmd/workbench`
  因并行会话在途测试的 **`hiddenTestCmd` 重复声明**失败 —— 冲突在 `headless_test.go:32`（已跟踪）
  与 `headless_testcmd_windows_test.go:19`（未跟踪）之间；**其余 30/30 个包 vet 全过**，阻塞面就这一个包。
  注意 `-SkipTests` 绕不过：它只跳过 build.ps1 第 4 段，第 3 段的 `go vet ./...` 照跑（实测 `build.ps1:103`
  无条件执行）。逐行定位与三个解铃选项见 `docs/handoff/在途件交接记录-2026-10-23.md` §7。
- **建议**：由收尾 `workbench/cmd/workbench` 在途测试的会话收敛重复声明后跑 `setup/build.ps1`。
  详见 `docs/handoff/在途件交接记录-2026-10-23.md` §6。

### 3.2 未跟踪 Go 测试（并行会话所有权；2026-10-25 实测 29 个）

- `check_untracked_go.ps1` 每轮记录数量与健康度（是否正在失败）。
- **2026-10-25 更新**：全仓 `go test ./...` FAIL 包数已归 **0**（并行会话解掉了 hiddenTestCmd
  重复声明并入库 2 个未跟踪生产件）—— 原记的「3 个包因它们而红」是当时的实况，现已不成立。
- **建议**：不代改（所有权在他人）；本仓已有健康度读数序列，可直接判断「红了多久」。
- **本段暴露的盲区（如实登记）**：`check_report_figures` 只校验开头规模表的四个数字，
  像本节这样写在正文里的「现状型数字」它管不到 —— 标题的 31 就是靠人工复核才发现过期。
  暂不扩判据：给每个正文数字定义实测来源会牵动大量文本、易生噪声（round 64 教训）；
  改为**约定**：正文写现状数字时带日期与「实测」字样，过期可由 `check_comment_staleness`
  的同类人工走查发现（本节已按此改写）。

### 3.3 24h soak 门槛未达

- 活实例已运行 17+ 小时，距 `--soak` 的 24h 门槛还差约 6h。趋势算法已修好（round 39），
  剩下是**攒实时长**，不需要额外工作。

### 3.4 一处刻意的「不做」

- `性能基线口径.md` §9 记录了两个内存口径（RSS vs HeapInuse，实测带 1.5×~3.8×）不可互比。
  **未设门禁**是刻意决定：跨口径互比属语义问题，硬做判据会制造噪声 => 触发本仓在册的
  「模糊语义检查 => 门禁被删」。留档在权威文档、由评审把关。

## 5. 结论

门禁体系当前 **45 个判据 / 27 个进 CI / 0 个孤儿 / 8 类已知失效形态均有护栏**（round 164 起：44 个受跟踪门禁，其中 26 个进 repo-gates，其余经 build job 的构建链、提交前闸或本地套件执行。**round 192 更正**：原记 27 —— 提交前的索引 BOM 闸挂在 CI 上但那里暂存区恒空、只会 exit 0 不判任何东西，属「看起来有覆盖、实际没在判」，已移出清单；它真正的受理面是 .githooks/pre-commit。**round 222 更正**：新增 check_crossbuild（交叉编译判据，起因是带 `//go:build !windows` 的文件里的未用 import 让 Autonomy E2E 连红 6 个提交，而 windows 上的 vet/test/build 永远编译不到那些文件），故现为 45 / 27。）
剩余的实质问题只有 3.1（产物重建 —— 阻塞面已精确到 `cmd/workbench` 单包内的 `hiddenTestCmd`
重复声明）与 3.2（在途测试），
两者都不是「缺少判据」，而是「等人收尾」——报告如实标出边界，不假装已解决。
