# 提交前闸（git hooks）启用说明

> **一句话**：本仓的 pre-commit hook 文件已受版本控制，但 **`core.hooksPath` 写在 `.git/config`，
> 不随 clone 传播** —— 所以每台新机器 / 每个新 clone / CI 都需要**显式启用一次**。

## 启用（一条命令）

```powershell
powershell -ExecutionPolicy Bypass -File setup/install-hooks.ps1
```

## 它做什么

提交时对**已暂存的** `.go` 文件跑 `gofmt` 检查（判据在 `tests/check_staged_gofmt.ps1`）：
未格式化的文件会被**拦在本地**，而不是等 CI 五分钟后判红、再补一轮提交。

与 CI 的 `check_gofmt.ps1` 分工：后者判 **HEAD 全树 + 债务豁免过期**，
前者判**暂存区**（本地秒级反馈）。两者都过才提交，是最快路径。

## 验证是否生效

```powershell
powershell -File tests/check_hooks_enabled.ps1
```

PASS = 闸门已装；FAIL 会给出修复命令。

## 卸载

```powershell
powershell -ExecutionPolicy Bypass -File setup/install-hooks.ps1 -Uninstall
```

## 紧急跳过

```bash
git commit --no-verify
```

但 CI 的 `check_gofmt` 仍会判红 —— 代价更大，仅建议用于「明知要修、先提交一版」的场景。
