## 1. 正确性（本次主发现 · P1）

### 1.1 族 A：注释承诺 ≠ 实现（4 例，全部已修）

| 位置 | 注释承诺 | 实测行为 | 后果 |
|---|---|---|---|
| `cmd/workbench/ui_probe.go` 的 `parseIntArg` | 「拒绝 "12abc" 这类半数字」 | `Sscanf("%d")` 只取前导整数 | `"12abc"`→12、`"1e3"`→1、**`"0x10"`→0**（`--port` 静默变内核随机端口） |
| `cmd/workbench/prune.go` 保留天数 | （无）`fmt.Sscan` | `"3abc"`→3、**`"0x10"`→16** | 这三个数字是**保留天数**，`--apply` 不可逆 ⇒ 按错误年龄删数据 |
| `internal/browser/browser_windows.go` 的 `headless` | 「大小写不敏感」 | 硬编码白名单（8 个字样） | `tRuE`/`Yes`/`On`/`" true "` 全不认 ⇒ 测试与无人值守**照样弹窗** |
| 同上文件的 `Open` | 「配合 CREATE_NO_WINDOW 保证不闪壳窗口」 | 只有 `HideWindow: true` | GUI 子系统里仍可能闪壳窗口（同文件回落路径 L51 反而带了 flag） |

**共同形态**：注释（或文件名）承诺一个语义，实现给了另一个；而**两边都没有任何判据**。
**已落地判据**：`headless` 收敛为一份并补 5 条测试（含 `Open` 无头时不得起进程）；
`SysProcAttr` 字面量维度并入 `check_spawn_silent.ps1`（见 §4.2）。

### 1.2 族 B：同一口径多份实现漂移

- `headless()`：`browser_windows.go` / `browser_other.go` / `cmd/workbench/headless.go` **三份**，
  只有 cmd 侧那份是对的且有测试。已**收敛为一份跨平台实现**。
- `hiddenProcAttr` 一族：`hiddenProcAttr` / `hiddenAttr` / `hiddenSysProcAttr` / `hiddenCmdAttr` /
  `job_windows` …**7 个不同名字**（其中一处注释自承「长期应统一到一个公共包」）。
  **本轮只修了漏点、未做收敛**（理由见 §6.2）。

**测量口径（round 170 实测）**：扫描受跟踪非测试 `.go` 的函数定义 → 1184 定义 / 1026 个不同名 →
**跨包同名且实现不一致 77 组** → 再用「体 ≤16 行 **且** 词集相似度 ≥0.5」细化到 **12 对**。
77 → 12 的收窄说明：**「同名」本身几乎不含信息**（`New`/`Get`/`Run` 在不同类型上合法），
只有「小工具体 + 高相似度」才是漂移信号。首版我按「同名」直接输出 77 组，是**噪声当发现**。

### 1.3 族 C：判据空转（本会话最贵的一处）

`check_deadcode.ps1` 一直报「无死代码」，**同树同时刻实测真实有 16 处**。两处叠加缺陷：

1. **引用计数把注释也算成引用** —— Go 惯例是函数自己的文档注释以函数名开头 ⇒ 「凡有文档注释的未导出
   函数」全都对本判据隐形，它实际只能抓「完全没被提及的函数」；
2. **抽取用 `-match`**（PowerShell 默认不区分大小写，.NET 的 IgnoreCase 也作用于 `[a-z]` 字符类）
   ⇒ **537 个导出定义**进了候选；改 `-cmatch` 后候选 38 → **16**（真值）。

**判据的判据**：这道闸同时说明「**判据自身也要有覆盖证明**」——它自己是绿的，却什么都没在判。

## 4. 安全

### 4.1 大小写口径（issue form 闸）

`check_issue_forms.ps1` 全程用 `-match` 解析 YAML 键，而 GitHub schema 的键**全小写** ⇒
`Type: dropdown` / `Required: True` 会被判合格、**却被 GitHub 静默忽略**（正是该闸开头写的危害）。
修法**刻意不换 `-cmatch`**（那会让变体键「不成块 ⇒ 被跳过」，等于从「误判合格」变成「静默不判」），
而是把**键名大小写不符显式判为违规**并点名应为的小写形式。

### 4.2 控制台静默维度

`check_spawn_silent.ps1` 此前只扫「已知控制台二进制（cmd/reg/powershell/pwsh/wmic）的 spawn」，
且只要求「±几行窗口内有任一隐藏标记」⇒ **GUI 目标不在面内**、**只写 `HideWindow` 也算合规**。
已并入第二维：每个 `SysProcAttr{...}` 字面量必须**同时**有 `HideWindow: true` 与 CREATE_NO_WINDOW
（字面量或**定义处即该值**的常量名，数据驱动允许改名）；`!windows`/`_other.go` 豁免。

   **该项已落地**（round 176 用 `go/parser` 把判据扩到全部 13 个内嵌块，含 `appJS`/`poolJS`/`govJS`）；

## 7. 我自己的错（本段 4 次，全部当场自纠）

1. **查错路径下结论**：按猜出的 `workbench/app.rc`、`workbench/rsrc_*.syso` 判定「资源件不在库、
   产物将丢图标与版本」；回 `setup/build.ps1` 读 `$build` / `$sysoDst` 定义后发现真实路径是
   `workbench/build/app.rc` 与 `workbench/cmd/workbench/rsrc_windows_amd64.syso`（**在库且有效**）。
   结论在写进交付物之前被自己推翻。
2. **无效变异**：删 `verify ⑩` 时忘了把上一行行尾的引号收口 ⇒ 编译错；判定器正确标为
   INVALID(compile) 而非 RED OK。同类还有一次「replace 没命中」导致 SILENT。
3. **判据假阴性**：`SysProcAttr` 第二维第一版的常量表把「任何含 `0x08000000` 与 `=` 的行」上
   **所有**标识符（含 `HideWindow`、`cmd`）都收进表 ⇒ 漏 flag 的站点靠 `Contains(HideWindow)` 通过
   （变异后仍 PASS）。改成只认「常量定义行」后变异正确判红。**教训：判据取值来源必须窄而准**。
4. **自检探针串打错**：条款⑥复核时把「不闪黑框」写成「裸黑框」得到 False，随即用正确串复验。
