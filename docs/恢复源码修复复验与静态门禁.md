## 2. 新增：整仓枚举一致性扫描（低噪声版）

`tests/docker-autonomy/consistency-scan.sh`

**判据设计**（关键在"抑制误报"，否则噪声会淹没真信号）：

对每个枚举族（同文件同类型名的 `TypeXxx Type = "值"` 常量）：
1. 统计全仓以 `case <常量>:` 出现的该族成员数 N_case；
2. **N_case == 0 → 不报**（该枚举靠 `==`/`map` 消费，是最常见的正常形态）；
3. **N_case > 0 → 存在 switch 分发器**，此时族内没有任何 case 的成员 = 漏项，报 WARN。

**首版被我自己否掉了**：只查"有无 case"的版本在恢复树上刷了 **70 条 WARN**，
逐条核对后**全是误报**（那些枚举本就用 `==` 或 map 消费，不需要 case）。
噪声版门禁会被忽略，等于没门禁 —— 故改成上面的收窄判据。

## 3. 变异测试：证明新判据真的有效（不是"永远绿"）

把修复好的 `acceptance.go` 复制一份，**人工删掉那两个 case**，再跑扫描器：

| 输入 | 输出 |
|---|---|
| 修复后的树（正常） | 枚举族 0 WARN；`CriterionKind 声明 7 / 处理 7` |
| 人工删除两 case（变异体） | **`CriterionKind 声明 7 / 处理 5`** + WARN「声明数与处理数不一致 ⇒ 有判据会被 default 按未通过处理」 |

→ 判据能**复原出它当初抓到的那个缺陷**，说明不是恒绿的空判据（变异体已清理）。
