# 纯净检出门禁的并发互删假红 —— 五轴审查报告（2026-10-25 · round 121-123）

> 范围：`tests/check_snapshot_build.ps1`、`tests/quit_mutation_check.ps1`、`tests/keepalive.ps1`、
> `tests/aggregate/agg_e2e.ps1`。可直接贴 PR。所有结论有实测出处；**没测成的都标明**。

## 0. 触发与结论先行

全量 check_all 出现过一次 `FAIL 纯净检出编译`，但我单独重跑同一门禁是 **PASS**，
复跑全量也是 **36 PASS / 0 FAIL**。"偶发红"若不归因，下次会再撞，且会被当成真缺陷追查。

**结论：门禁自身的临时目录竞态造成假红 —— 红的是判据实现，不是被检查的提交。**
已修复两处（递归删互撞），并顺手接上一个"声明却从未使用"的超时参数。

## 1. 正确性（主发现）

- **P1｜临时目录名只到秒，同秒两次调用得到完全相同的名字。**
  机制实测（不是推理）：

  ```powershell
  $old1 = 'wb-snapshot-' + [DateTime]::Now.ToString('HHmmss')
  Start-Sleep -Milliseconds 300
  $old2 = 'wb-snapshot-' + [DateTime]::Now.ToString('HHmmss')
  # 旧命名同秒两次: wb-snapshot-033919 vs wb-snapshot-033919 相同=True
  # 新命名两次(GUID): wb-snapshot-dc3b2570 vs wb-snapshot-00ca1b84 相同=False
  ```

  本仓的既定现实是**多会话同机并发**（handoff §10 已两次实证共享 index 竞态）。
  门禁的 `finally` 里有 `Remove-Item -LiteralPath $tmp -Recurse -Force`，
  于是两个并发实例会**互删对方的快照树**；正在编译的一方随即报缺文件而 exit 1。
  这就是那次"单独跑绿、check_all 里红"的成因（时序上我的复跑与该段并发重叠）。

- **更正（round 123，实测证伪我自己的归因）**：上面那句**未经证实**，且大概率是错的。
  后来抓到那次红的确切来源：CI run 40127263998 的快照 job 里失败的是我 round 121 写的
  `TestWriteDocxConcurrentExportsAllSucceed`，报「替换目标文件失败（已从备份恢复）:
  rename … being used by another process」—— 真凶是 `config.WriteFileAtomic` 的同路径
  并发竞态（生产缺陷），不是 Temp 目录撞车。本机无锁版复现率约 1/30、带锁版 0/30。
  Temp 唯一名这条改动本身仍成立（机制实测：同秒 HHmmss 命名相等=True，且 finally 有
  `-Recurse` 删），但它治的是「潜在互删」，不是那次实际发生的红。

- 同形态第二处：`quit_mutation_check.ps1` 用**固定名** `wb-mutation-ka`，
  且前置删（L107）+ 后置删（L122）都是 `-Recurse` —— 两个会话同跑时，后启动者的
  前置删直接删掉前者正在使用的变异体目录。**修法同上（GUID 后缀）**。

- 修复用本仓既有惯例，不发明新模式：`e2e_soak` / `selfheal_e2e` / `e2e_workspace` /
  `failover_evidence` / `check_staged_gofmt` 都已经是
  `[guid]::NewGuid().ToString("N").Substring(0,8)` —— 这两处只是**漏网的**。

## 2. 可读性 / 3. 架构

- **P2｜`[int]$TimeoutSec = 300` 声明了却全仓无人使用**（`git grep TimeoutSec` 在本门禁
  只出现 1 次，即 param 声明本身）。属本仓在册的第三种失真形态 —— 「文档承诺比实现新」：
  头部写着超时，实际任何一步挂住都会一直挂着。
  已接进 `go test -count=1 -timeout ("{0}s" -f $TimeoutSec)`，**两处调用都接**（首轮 + flaky 重试）。
  安全性实测：`-timeout` 约束的是测试二进制执行时长（不含编译）；逐包耗时实测最慢
  `cmd/workbench 45.1s`、`engine 26.0s`，300s 余量 **6.6×** ⇒ 不会引入新假红。
  格式化结果实测为 `300s`（String，长度 4），并用它实跑一包 rc=0。
- **附带发现（未改，登记）**：`.github/workflows/ci.yml` **没有任何 `timeout-minutes`**
  （全文 grep 0 处）—— CI 侧比本地更依赖这个接上的超时。
- 架构面无问题：门禁"导出 HEAD 快照再从零编译"的设计是对的（它确实抓到过 4 个文件
  从未入库的事故），问题只在实现细节的命名唯一性。

## 4. 安全 / 5. 性能

- **两轴均未发现问题**，且不是没看：临时目录在 `$env:TEMP` 下、内容是从本仓 HEAD
  导出的源码快照，不含凭据；删除一律用 `-LiteralPath`（无通配展开风险）。
  性能上 GUID 命名零成本，且把"挂死等整段超时"变成 300s 内带栈输出退出。

## 未修的两处（如实登记，不假装覆盖）

| 处 | 命名 | 为什么暂不改 |
|---|---|---|
| `keepalive.ps1:186` | 固定名 `wb-keepalive-out.log` | 只是 `-RedirectStandardOutput` 的落地文件，**全仓无删除动作**；并发互写最坏是日志混排，不产生假红。改它需先确认 keepalive 的进程间契约（该件在跑 7×24 保活，本轮不动）|
| `aggregate/agg_e2e.ps1:11` | 固定名 `wb-agg-e2e` | 不在 check_all 常规段；且 `agg_e2e.py:19-20` 有**同名兜底路径**，改唯一名要同步改 Python 侧否则读不到 ROOT。属"改一处需动两处"的独立小轮 |

## 合并结论

**可合并。** 依据：

1. **改动最小且语义等价**：只把目录名从"秒级/固定"换成 GUID 后缀，变量流全部经同一
   变量传递（逐行核过 `$mutantDir`/`$tmp` 的全部引用：5 处与 6 处，无第二处硬编码字面量）。
2. **实跑通过**：`check_snapshot_build` 改后 rc=0（go build + go test 两段都过）；
   全量 `check_all` **36 PASS / 0 FAIL**。
3. **门禁四件套全绿**：`check_ps1_syntax` / `check_multi_bom` / `check_ps1_eol` /
   `check_ps1_encoding` 均 PASS；两文件编码写回后**逐字节复核**（BOM 恰 1；
   snapshot 纯 CRLF 裸 LF=0，mutation 保持原有 LF 形态）。
4. `quit_mutation_check` 不在 check_all 常规段（实测 grep 确认），且它会起停真实进程 ——
   按「不为验证而打扰 7×24 实例」的纪律**未单独运行**，只做了静态变量流复核 + 语法门禁。

## 附：本轮我自己的四处测量错误（如实记，它们是方法教训）

按上一轮刚编码进 `quality-audit` 模板要求 ⑤ 的四条自查，本轮命中四处（含凭猜标识符）：

1. **分类器误判**：自动脚本把 `check_homepage`/`check_perf` 判成"同秒撞"隐患，
   实际它们的命名是 `yyyyMMddHHmmss` + `Get-Random -Maximum 9999` —— 我的正则只看了
   时间戳部分。**人工逐条读原始行**才发现，两处因此排除在修复范围外。
2. **PowerShell 正则空匹配**：用 `-match '\s(ok|FAIL)\s.*\d+\.\d+s'` 解析 go test 输出，
   得到「包数=0」并连锁触发 `$s[0]` 空索引崩溃。改为把输出落文件、用 Node 逐行解析，
   才拿到真实 29 包数据。**"零结果"要先怀疑测法，不是先怀疑被测对象。**
3. **锚点计数假设**：我以为两处 `go test` 调用行文本相同（早前输出被截断），
   按整行等值匹配只命中 1 处 —— 实际两处缩进不同（4 空格 vs 8 空格）。
   先 `JSON.stringify` 打出真实字节再改，避免了改错与漏改。

4. 凭猜标识符：直接猜门禁脚本名叫 `check_clean_checkout_build.ps1`（真名
`check_snapshot_build.ps1`），靠 `git ls-files` 列全名纠正 —— 正是刚写进模板的
「严禁猜标识符」，我自己本轮就破了两次，记在这里而不是藏起来。
