## 1. 五轴发现（P0 阻塞 / P1 应改 / P2 建议）

### 正确性
- 无 P0。5 个令牌既不被引用也不被读取，**当前不影响任何渲染结果** ——
  「死令牌」不是渲染 bug，是抽象层 bug。

### 可读性（本问题主战场）
- **P1-1｜虚假的抽象比没有抽象更坏**：`:root` 里写着 `--accent-3:#a78bfa; /* 副信号：紫（科技感的第二个记忆色）*/`，
  注释宣称它是「第二个记忆色」。但 L91 的紫色是**硬编码** `rgba(167,139,250,.055)`
  —— 167,139,250 正是 `#a78bfa` 的 RGB。即：**设计意图存在，但实现绕过了令牌**，
  读 CSS 的人会以为改 `--accent-3` 就能换掉全局紫色，改了却发现毫无效果。
  这是本轮最危险的一条：它不是「多余」，是「骗人」。
- P2-1：`--muted:#8fa6c0` 与在用的 `--dim:#7189a4` 语义重叠（都是弱化文字色）却并存，
  且实际只用了后者。两套名字表达一件事，是命名债。

### 架构
- **P1-2｜派生令牌链未闭合**：`--accent-soft: rgba(var(--accent-rgb),.14)`、
  `--scanline: rgba(var(--accent-rgb),.055)` 走的是「主色 → RGB 通道 → 透明度」的三层派生，
  这套机制本身是对的（`--scanline` 本轮已被用起来）。但 `--accent-soft` 这层没人用 ——
  半透明主色底（选中态/hover）在实际 CSS 里各写各的。缺的是**约定**，不是机制。
- P2-2：`--glow-violet` 是一个完整 box-shadow 值（`0 0 28px -10px rgba(...)`）。
  把「整条阴影」做成令牌粒度偏粗：复用时无法只换颜色不换偏移。
  建议改拆为 `--accent-3-rgb` 通道 + 使用点自组合（与 `--accent-rgb` 同构）。

### 安全
- 无发现。这些是纯视觉令牌，不涉注入/越权；且 `getPropertyValue` 零读取，
  删除不会产生「JS 读不到样式值」的降级路径。

### 性能
- 无发现。CSS 变量解析开销与是否被引用无关，5 个死令牌**不构成性能负担** ——
  这一点要写明白，否则容易被误当成性能问题去优化（真实动机是可维护性）。

## 2. 处置建议（按优先级，每条可独立执行）

| # | 动作 | 影响面 | 风险 |
|---|---|---|---|
| P1-1 | 让紫色族「用起来而非删掉」：加 `--accent-3-rgb:167,139,250`，把 L91 等硬编码紫换成 `rgba(var(--accent-3-rgb),α)` | 视觉零变化（同值替换）| 低（可双向核验，同前两批做法）|
| P1-2 | 定「半透明主色底」用 `--accent-soft`，把散落的 `rgba(var(--accent-rgb),.1x)` 收编 | 需逐个核对 α 值是否等于 .14 | 中（α 不同不可换，须逐处判）|
| P2-1 | `--muted` 与 `--dim` 二选一，另一个删除 | 只删定义行 | 低 |
| P2-2 | `--glow-violet` 拆成 rgb 通道 | 使用点尚未存在，纯定义改动 | 低 |
| — | 若 P1-1/P1-2 判定「设计不再需要紫/柔底」，则直接删定义 | 5 行删除 | 低（零引用零读取）|

**建议顺序**：先 P1-1（消除「骗人的抽象」，且是纯同值替换最安全），再 P2-1 收命名债，
P1-2 需要逐个 α 判断放最后。**不要**一次做完 —— 违反逐点攻破。

## 3. 合并结论

- **本轮（round 99）可合并**：`--scanline` 复活（1 处同值机械替换）+ 基线 6→5 条 + 本报告。
  证据：gofmt clean；`go test ./internal/web/` rc=0；`check_dead_css_tokens` rc=0 且
  summary 自洽（44 在用 + 5 登记 = 49）；大括号数 474 不变（无结构改动）。
- **剩余 5 个死令牌 = 已登记债务，不是待修 bug**：基线 `tests/css-token-debt.txt` 逐条打印，
  门禁不因它们判红，但**禁止新增**（新死令牌当场拦）。

## 4. 门禁建议

1. **已具备**：`check_dead_css_tokens.ps1`（判新增）+ `tests/css-token-debt.txt`（管存量）。
2. **建议增补（P2，未实施）**：门禁目前只认「名字出现次数 ≤1」，无法区分
   「该令牌被注释提到」与「被 var() 真正引用」。当前用非注释行统计已规避大半，
   若要更严可改为**只数 `var(--x` 形态** —— 但收益有限（现有实现本轮已能抓到真缺陷），
   暂不做，避免过度工程。
3. **不建议**做的事：把「硬编码色值数量」做成判据（如「CSS 里 hex 色不得超过 N 个」）。
   这需要一次性梳理 38 个唯一色值，属宏大目标；且阈值型判据必然产生噪声
   （本仓在册：模糊/过宽判据 => 门禁被撤）。
