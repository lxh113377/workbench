# 自主运行方案 — 动态任务规划 × 闭环自主执行 × 边界与回退

> 版本：v1.3.0（2026-10-19）｜对应目标要求 1-4
> 代码：`workbench/internal/autonomy`（纯逻辑）＋ `workbench/internal/engine/engine_autonomy.go`（接线）
> 入口：面板「自主」页签 ｜ CLI `workbench.exe --autonomy` ｜ API `/api/autonomy*`
> 离线验收：`workbench.exe --autonomy selftest`（11 项，退出码 0/1）

---

## 1. 改造前为什么"不自主"

| 现状 | 证据（改造前代码） | 后果 |
|---|---|---|
| 任务只能从 24 条固定模板生成 | `engine.supplyCandidates` 遍历 `registry.Enabled()`，每条模板用 `RootTask(tpl)` 渲染 `{topic}` | AI 永远在回答"模板里的问题"，不会推导"项目下一步要做什么" |
| 后继任务只能沿父模板的固定后继表 | `chain.SuccessorTemplates` 读 `tpl.Chain.SuccessorTemplates`，`extendChain` 按 fanout 延伸 | 链是"模板图"而非"目标树"，走完就断 |
| 无项目级目标概念 | `model.Task/Chain` 没有 goal 字段，`config.Config` 没有 autonomy 段 | 没有"整体目标"可依据，"阶段性目标"无从谈起 |
| 自评只打分、不闭环 | `postProcess` 拿到 `Critique.Quality` 后仅 `SetChainQuality` 与链式生成 | 质量低就"不再延伸"，但没有回退、重规划、预算与验收 |
| 无自主边界与预算 | 只有 `Eval.DailyCap`（每日任务数）与 `Chain.MaxDepth` | 若直接放开生成，重复/越界/人工不可完成任务会直接进执行队列 |

结论：改造前是"**模板驱动的自动产出**"，不是"**目标驱动的自主运行**"。要满足目标要求 1-4，必须补上三层：
**目标层（Goal/Stage/Criterion）→ 决策层（Planner/Bounds/Risk）→ 闭环层（Acceptance/Rollback/NextGoal）**。

## 2. 总体架构

```
                     ┌──────────────────────────── 项目核心目标（Goal） ───────────────────────────┐
                     │ title / intent / domain / criteria[] / stages[] / budget / status           │
                     └───────────────┬───────────────────────────────────────────────▲─────────────┘
                                     │ 读取目标与当前执行状态                          │ 目标完成 → 推导下一目标
                                     ▼                                               │
  ┌──────────────┐   草案    ┌────────────────┐  边界校验  ┌──────────────┐   任务   │
  │  Planner     │ ────────▶ │  Bounds (B1-B4)│ ─────────▶ │   Engine     │ ────────┘
  │ 动态任务规划  │           │ 结构化/语义/领域/预算        │  调度+执行    │
  └──────▲───────┘           └────────────────┘            └──────┬───────┘
         │ 自评 gaps / nextIdeas / 阶段序号 / 近期标题               │ 任务完成 + 自评
         │                                                        ▼
  ┌──────┴───────────────────────────────────────────────────────────────┐
  │  Risk(质量/空转/预算) → JudgeStage → Acceptance(目标级验收) → Rollback │
  │  全部留痕：goals.json（状态）+ decisions.jsonl（原因，append-only）      │
  └──────────────────────────────────────────────────────────────────────┘
```

**分层原则**：`autonomy` 包只做纯逻辑（可单测、零外部依赖：仅 `model`/`config`）；
引擎只负责"在正确时机调用 + 翻译成任务与事件"。这样规划逻辑可离线验证，调度逻辑保持原样。

## 3. 核心模块实现逻辑

### 3.1 目标模型（`types.go`）

```go
type Goal struct {
    Title, Intent, Domain string      // 项目级目标（自然语言意图注入 Prompt）
    Status        GoalStatus          // active / completed / blocked / abandoned
    Criteria      []Criterion         // 机器可判的验收标准（目标完成的唯一依据）
    Stages        []Stage             // 阶段轨迹（每阶段 = 一条任务的产出与自评）
    Evidence      []Evidence          // 验收证据（任务 ID / 质量 / 字数）
    Rollbacks     int                 // 已回退次数（预算）
    MaxTasks, MaxStages, MinQuality   // 该目标的预算快照
}
```

- **Criterion 四类**：`tasksDone`（完成阶段数）、`minQuality`（自评均分下限）、
  `minWords`（总字数下限）、`distinctDomains`（领域覆盖）。全部可从既有台账计算，
  **验收本身不额外调模型**（零成本、可重放）；`manual` 判据不参与自动判定，留给人工。
- **Stage 记录 `Quality/Words/Passed/Note`**：自评质量与字数由引擎在任务完成时写入，
  这是"目标完成到什么程度"的持久化事实，不是内存推断。

### 3.2 动态任务规划（`planner.go`）

规划器输入是"目标 + 当前状态"，不是模板池。两条路径：

1. **模型自评驱动**（优先）：上一任务的自评给出 `gaps`（不足）与 `nextIdeas`（后继方向）。
   这本身就是模型对"下一步做什么"的判断；规划器把它改写成带项目目标上下文的可执行 Prompt。
2. **领域阶梯兜底**（保证不断线）：`domainLadder` 把每个领域的推进拆成 5 级
   （如 content：立框架 → 补证据 → 成文 → 再加工 → 复盘），按 `len(goal.Stages)` 取当前级。

生成规则：
- Prompt 必含 **项目核心目标 + 当前阶段焦点 + 已完成阶段 + 上一轮不足** —— 这是与固定模板的本质区别；
- 标题与近期产出去重（前缀 12 字相同视为重复）；
- 每轮最多 `Plan.MaxDrafts` 条（默认 2），防止扇出爆炸；
- 全部输出必须过 `Bounds.ValidateDraft`。

### 3.3 自主验收（`acceptance.go`）

任务完成 → 引擎在 `postProcess`（拿到自评后）调用 `Manager.CompleteStage`：

```
JudgeStage(质量是否达标) → CheckStageRisk(质量/空转/预算) → 回退或计入
   → Evaluate(目标级验收：逐条标准算现值/阈值/差额) → 全部通过 ⇒ Goal.Completed
   ⇒ advanceLocked(自动推导并激活下一目标，闭环续跑)
```

每条标准都回写 `Current/Threshold/Passed/Detail`，所以"为什么没通过"是可解释的
（例：`完成不少于 4 个阶段（现 2 / 需 4，还差 2）`），不存在黑箱验收。

### 3.4 边界约束（`bounds.go`：B1-B4）

| 编号 | 边界 | 判据 | 处置 |
|---|---|---|---|
| B1 | 结构化 | 标题 4-80 字、Prompt 30-4000 字、必须含可交付物动词（产出/输出/写出/生成/分析/整理/设计/实现/拆解/总结） | 超长**自动裁剪**留痕；过短/无动词**拒绝** |
| B2 | 语义 | 关键词黑名单：登录/扫码/付款/验证码/人工审核/提交表单/密码/API Key/实名认证… | **拒绝**（本机自主通道必然做不成，别浪费 3 次重试） |
| B3 | 领域 | `Bounds.AllowedDomains` 白名单（默认六大领域），非法领域剔除/回退默认 | **拒绝**非法领域 |
| B4 | 预算 | 单目标 `MaxTasksPerGoal/MaxStages/MaxRollbacks/MinQuality`，`Normalize` + `ClampBudget` 双道钳制 | 超限 ⇒ 目标 `blocked` |

B1 的"能修的修、不能修的拒"是刻意设计：一个超长标题不该卡死整条自主线，
而"需要人工登录"这类任务必须死在规划期而不是执行期。

### 3.5 风险校验与异常回退（`risk.go`）

| 风险 | 触发 | 动作 |
|---|---|---|
| R1 质量风险 | 阶段自评 < `MinQuality` | 阶段 `Passed=false` + `Goal.Rollbacks++` + 记 `rollback` 决策；**不删除任何已产出文件**（软回退） |
| R2 预算风险 | 阶段数/回退次数达上限且验收未通过 | 目标 `blocked` + 记 `block` 决策 + 面板"恢复该目标"按钮 |
| R3 空转风险 | 标题与近期产出高度相似 | 记低风险提示（默认不阻塞，可通过 `Risk.BlockOnRepeat` 升格） |

**回退语义**是软回退：产出可查、历史任务状态不改、人工可恢复（`--autonomy` / 面板恢复），
因此自主循环失控时永远有"回到人类手里"的通道。

### 3.6 兼容性：固定模板链路一条都没动

- `supplyCandidates` 现在先调 `supplyAutonomous`；返回 false（关闭自主/目标完成/阻塞/预算耗尽/草案全被拒）
  ⇒ **原样落回模板池逻辑**（代码路径与改造前完全一致）；
- `postProcess` 里只有 `Source=="autonomy" && GoalID!=""` 的任务走自主验收，
  模板/链/合成任务照旧走 `extendChain`；
- `Autonomy.Enabled=false` 时引擎行为与改造前逐字节一致（有单测 `TestSupplyCandidatesUsesTemplateWhenAutonomyOff` 守护）。

### 3.7 持久化与可审计（`store.go`）

- `workbench-output/autonomy/goals.json`：目标树，原子写（tmp→fsync→rename）；
  损坏时备份 `.corrupt-<ts>` 并重建空树，**不阻断启动**；
- `workbench-output/autonomy/decisions.jsonl`：决策台账，**只追加**，
  每行 `{at, goalId, taskId, kind, reason, evidence, actor}`；
  覆盖 plan/accept/reject/rollback/goalDone/nextGoal/block/boundReject/resume 九类；
- 目标树超过 60 个时自动归档最老的终态目标（活跃目标永不裁剪）。

## 4. 与引擎的接线（四处，最小侵入）

| 位置 | 调用 | 作用 |
|---|---|---|
| `Engine.New` → `initAutonomy` | 打开仓储 + 构造 Manager | 初始化失败只降级（日志 warn），不阻断引擎 |
| `Engine.Start/Recover` | `bootstrapAutonomy` | 有活跃目标复用；已完成则推导下一目标（重启后续跑） |
| `supplyCandidates` | `supplyAutonomous` | 队列水位低于并发数时，先由目标规划一条任务；失败回落模板 |
| `postProcess` | `finishAutonomous` | 自主任务完成 → 质量判定/风险/验收/回退/下一目标推导，并推送 `autonomy` 事件 |

自主任务用同一条链 ID（`autochain-<goalID>`），复用队列的"每链串行"保证阶段顺序执行
（阶段 N+1 依赖 N 的产出），不需要新增调度语义。

## 5. 验证标准（可复跑、可判真假）

### 5.1 离线自检（无需模型、无需网络）

```powershell
workbench.exe --autonomy selftest
# 期望：11 PASS / 0 FAIL，退出码 0
```

覆盖：目标创建 → 动态规划 → 边界拒绝 → 高质量计入 → 低质量回退 → 目标完成 →
自动下一目标 → 持久化恢复 → 决策台账五类齐全。

### 5.2 单测与覆盖率

```powershell
cd workbench; go test ./internal/autonomy/ -count=1 -cover
# 期望：ok，coverage >= 70%（实测 76%+）
go test ./internal/engine/ -run 'Autonomy|Autonomous' -count=1
```

关键用例（判据而非形式）：

| 用例 | 判据 |
|---|---|
| `TestValidateDraftRejectsDangerousContent` | 5 类越界（空标题/空Prompt/人工介入/无交付物/领域越界）全部被拒 |
| `TestPlannerPrefersCritiqueIdeas` | 自评 nextIdeas 被优先采纳为下一条任务 |
| `TestPlannerLadderAdvancesWithStage` | 阶段推进后任务变化（不是同题重跑） |
| `TestCompleteStageAdvancedAndCompletesGoal` | 达标后目标完成并自动激活下一目标 |
| `TestCompleteStageRollsBackLowQuality` | 低质阶段回退且不计入进度 |
| `TestBudgetBlocksGoal` + `TestResumeGoal` | 预算耗尽阻塞、人工可恢复 |
| `TestPersistenceAcrossReopen` | 重启后目标/阶段/决策完整 |
| `TestSupplyCandidatesUsesTemplateWhenAutonomyOff` | 关闭自主后行为回落模板（兼容性） |

### 5.3 CLI 可观测验收

```powershell
workbench.exe --autonomy status   # JSON：active 目标 + criteria + stages + 最近决策
workbench.exe --autonomy plan     # 人类可读：当前目标 / 阶段 / 规划依据 / 完整 Prompt
workbench.exe --autonomy decisions 20
```

### 5.4 面板验收

管理面板 → 「自主」页签：目标状态/进度/回退 KPI、验收标准进度条、阶段轨迹、
决策台账、目标树；blocked 目标显示"恢复该目标"按钮。

### 5.5 端到端（真实模型跑通闭环）

启动引擎后观察：事件流出现 `autonomy` 事件（自主规划 → 自主验收），
`workbench-output/autonomy/goals.json` 的 `stages` 随产出增长，
`decisions.jsonl` 依次出现 `plan → accept → goalDone → nextGoal`。
（该段依赖 OFM 通道，属于运行时验收，不放进离线 CI 判据。）

## 6. 风险清单与处置

| 风险 | 表现 | 处置 | 回滚方式 |
|---|---|---|---|
| 自主循环空转 | 反复生成相似任务 | R3 重复提示 + 规划去重 + 领域阶梯推进 | `autonomy.enabled=false` |
| 预算失控 | 任务数/阶段数无上限 | B4 硬预算 + Normalize/ClampBudget 双道钳制 | 改预算需重启生效；超限自动 blocked |
| 低质产出污染目标 | 自评低分仍推进 | 软回退 + 回退计数 + 超限阻塞 | 面板恢复目标清零回退 |
| 验收标准定义过松 | 一步就"完成" | 默认标准强制 ≥2 阶段 + 质量 + 字数 | 人工 `--autonomy goal` 重设 |
| 目标文件损坏 | 启动异常 | 备份 `.corrupt-*` + 重建空树 | 用备份文件替换回 goals.json |
| 自主与模板互相打架 | 队列被自主任务灌满 | 队列水位控制（< 并发数才补）+ 自主任务优先级 4 | 关自主即恢复纯模板 |
| 规划器引入新依赖 | 包间循环/不能单测 | autonomy 只依赖 model/config（硬约束，code review 卡点） | — |

## 7. 配置面（`config.json → autonomy`）

```json
{
  "autonomy": {
    "enabled": true,
    "budget": { "maxTasksPerGoal": 12, "maxStages": 6, "minQuality": 6, "maxRollbacks": 3, "stageEvery": 1 },
    "bounds": { "allowedDomains": ["content","code","knowledge","data","solution","report"],
                "maxTaskWords": 3000, "maxDraftsPerRound": 2 },
    "plan": { "rootTitle": "持续产出与能力沉淀", "rootIntent": "…", "defaultDomain": "content",
              "words": 1000, "maxDrafts": 2 },
    "risk": { "escalateMinQuality": 3, "blockOnRepeat": false },
    "rollback": { "onLowQuality": true, "onCostOverrun": true }
  }
}
```

所有数值越界由 `Config.Normalize()` 强制回到默认区间；文本为空补默认，不覆盖用户显式设置。
