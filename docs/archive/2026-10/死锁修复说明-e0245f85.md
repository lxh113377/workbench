# 死锁修复说明（会话 e0245f85 · 目录限定扩展线）

## 缺陷

`internal/workspace.Manager.SetConfig` 在**持写锁**期间调用 `validateNoAudit`，
后者经 `Mode() → Config()` 再取**读锁**；Go 的 `sync.RWMutex` 不可重入 ⇒ 永久死锁。

可感后果：**非 Windows 平台**（Linux 容器 / 服务器）上，配置为 external 模式时工作台**启动即挂死**：
`panel.url` 永不落盘、日志 0 字节、进程存活但不服务。Windows 本机因默认 project 模式而躲过。

## 触发条件（Docker 容器实测）

1. `--workspace select <dir>` 落盘 external 配置；
2. 再启动 `workbench --silent`：main.runApp:158 → `engine.ReloadConfig` → `ws.SetConfig` → 死锁。

## 修复（见本目录 wsfix/internal/workspace/workspace.go）

锁外校验 → 锁内纯赋值 → 锁外审计：

```go
var validated *Validation
if cfg.Mode == ModeExternal {
    v, err := m.Validate(cfg.Root)   // 锁外！Validate→Mode()→Config() 会取读锁
    if err != nil { return err }
    validated = v
    cfg.Root = v.Canonical
    if cfg.Since == 0 { cfg.Since = time.Now().UnixMilli() }
}
m.mu.Lock()
m.cfg = cfg
if validated != nil { m.lastValid = validated }
m.mu.Unlock()
if validated != nil { m.audit.Append(...) }  // 锁外审计
return nil
```

- `TestSelectExternalThenReloadRoundTrip`：模拟启动期 ReloadConfig 往返

实测：修复前两条均 5.00s 超时 FAIL；修复后 `go test ./internal/workspace/` = ok。
