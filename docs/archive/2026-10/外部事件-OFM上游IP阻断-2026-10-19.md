# 外部事件报告：OFM 上游 IP 被网络阻断（2026-10-19 20:2X-20:4X · ds 端）

## 现象
20:24:07 之后，所有模型尝试失败（10+ 次），错误一律是：
```
model request failed: connect ETIMEDOUT 144.126.133.165:443 (TRANSPORT)
```
每个 attempt 68-71 秒（连接超时），引擎逐模型换（互备机制正常工作），但全部撞同一面墙。

## 定位（实测）
| 检查 | 结果 |
|---|---|
| 144.126.143.165:443 直连 | **不通**（TcpTestSucceeded=False） |
| 该 IP 反解 | `vmi3660127.contaboserver.net`（Contabo 德国 VPS，OFM sealed 网关托管） |
| 经 7898 东京代理出口 | **也不通**（操作超时）⇒ 不是本机出口 IP 被封，是该 IP 本身不可达 |
| api.kilo.ai:443（kilo 官方） | **通** |
| 最后一个成功 | 20:24:06 dots-studio（kilo 车道，151s 完成） |

## 判断
20:24 前后，OFM 的 **sealed 网关 IP（144.126.133.165）从可达变为不可达**，
且换出口（东京代理）也无效 ⇒ 大概率是该主机宕机或被网络层阻断（GFW/上游故障）。
注意：OFM 插件的 kilo 车道请求实际也经过该网关（所以 kilo 模型一并失败），
虽然 kilo.js 的 KILO_BASE 写着 api.kilo.ai——**实际出口由插件的车道实现决定**。

## 影响
- 24h 产出**暂停**（引擎会继续每 68s 试一个模型，全部失败，直到网络恢复）；
- 这不是产品缺陷，是外部依赖故障。重试/换模型/守护都正常，等网络恢复即自动续跑。

## 已尝试的恢复手段
1. ✅ 重启 R2 留的临时 mihomo（7898 东京出口）—— 对该 IP 无效；
2. ✅ 确认 kilo 官方 API 可达 —— 但 OFM 插件不经它走；
3. ❌ 无法绕过（该 IP 是插件硬编码的 sealed 网关出口）。

## 建议（给老大）
1. **等**：IP 恢复后引擎自动续跑（无需任何操作，守护会保持进程活着）；
2. **观察**：若 30 分钟内不恢复，可能是该 VPS 宕机——可联系 OFM 插件作者或等其迁移；
3. **别重启**：重启不解决网络问题（守护已保证进程健康）；
4. 若要验证恢复：`Test-NetConnection 144.126.133.165 -Port 443` 返回 True 即恢复。
