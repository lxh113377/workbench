# 长时压测作业手册（A7 · 7×24 长期稳定性）

> 本文回答一个问题：**怎么证明这玩意儿能连续跑 24 小时不崩、不漏内存**。
> 判据由 `workbench.exe --soak` 出口承担，不靠人眼看数字。

## 1. 判据（机器判据，退出码即结论）

| 退出码 | verdict | 含义 |
|---|---|---|
| 0 | `ok` | 已覆盖 ≥24h 且堆内存/句柄无单调上升 |
| 2 | `leak` | 尾部均值显著高于头部且斜率为正（疑似泄漏） |
| 3 | `unknown` | 采样不足 / 跨度不足 / 文件缺失 —— **未验证，不得记 PASS** |

判定算法（`internal/supervisor/trend.go`）：

- 采样门槛：≥3 个点且跨度 ≥10 分钟，否则 `unknown`；
- 趋势：最小二乘斜率 + 首尾 1/3 均值双条件，同时满足才判 `leak`；
  （双条件是为了不被 GC 锯齿的单点尖峰带偏）
- 时长：默认要求覆盖 24 小时（`--min-hours` 可调），不足则 `unknown`。

## 2. 运行一条压测

```powershell
# 1) 准备一个独立目录（不要污染正在用的实例）
$root = 'D:\workdesktopuntime\soak-24h'
New-Item -ItemType Directory -Force -Path $root | Out-Null
Copy-Item D:\workdesktop\dist\workbench.exe (Join-Path $root 'wbsoak24.exe') -Force

# 2) 写配置：采样间隔压到 20 秒（默认 30 秒），并发保持安全值
#    注意：supervisor.sampleSeconds 只影响内存采样，metrics.csv 由主循环每 5 分钟落盘

# 3) 脱离当前会话启动（Start-Process 会被会话作业对象连坐杀掉）
$cmd = '"' + (Join-Path $root 'wbsoak24.exe') + '" --silent'
Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{ CommandLine = $cmd; CurrentDirectory = $root } | Out-Null

# 4) 24 小时后判定
& D:\workdesktop\dist\workbench.exe --soak --json "$root\workbench-output\logs\metrics.csv"
```

## 3. 关键坑（都已实测踩过）

| 坑 | 现象 | 处置 |
|---|---|---|
| `Start-Process` 启动的实例被会话连坐 | 启动 20-30 秒后进程消失、`panel.url` 在但连不上 | 用 `Invoke-CimMethod Win32_Process Create` 脱离作业对象 |
| 同名 `workbench.exe` 被其他会话 taskkill | 压测实例中途被杀 | 二进制改名（如 `wbsoak24.exe`） |
| `metrics.csv` 迟迟不出现 | 等了几十秒仍无文件 | 落盘由主循环 5 分钟 ticker 触发，首个样本要等首个 tick |
| Excel/记事本另存的 CSV 带 UTF-8 BOM | 表头被当坏行，首行采样静默丢失 | `ReadMetricsCSV` 已剥 BOM（有回归用例） |
| 端口冲突 | 压测实例用了 17895 | 配置里显式指定不同端口 |

## 6. 与 A7 的关系（诚实口径）

A7 的原文是「7×24 压测无崩溃无泄漏」。本手册交付的是**判据与工具**（可以客观回答『漏没漏』），
不等于『已经跑满 24 小时』。判定行：`--soak` 退出码 0 且 `spanHours >= 24`。
在此之前，A7 一律记为 `unverified`（不得写 PASS）。
