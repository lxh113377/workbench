## 三、未达成证据（不许含糊）

### 3.1 `goalDone / nextGoal` 未在真实通道出现

实测（隔离实例，20 分钟，真实模型通道）：

```
decisions: plan=4  accept=3        ← 闭环推进正常
stages:    #0 立框架 q=8  #1 补证据 q=10  #2 成文 q=9   (3/4)
criteria:  c-done 3/4 | c-quality 9/6 PASS | c-words 4912/3000 PASS | c-verified 0/2.4 FAIL
```

卡点：`c-verified` 要求阶段产出通过**真实执行验收**（模型按 `<<<ARTIFACTS>>>` 协议输出文件+验收命令）。
实测模型协议遵从率不稳定：stage#0/1 纯 Markdown；stage#2 出协议但 `python tool.py --help` 退出码 1 →
返工 1 轮后仍非全绿。故 `c-verified` 恒 0，目标永不可完成 → `goalDone/nextGoal` 不出现。

**这是产品缺口（判据 vs 通道真实能力不匹配），不是代码死锁**。两条候选路线见 `docs/自主运行-闭环死锁修复回执.md` §5。

### 3.2 「7×24 连续运行」只有机制与短时证据，无 24h 压测

已有：看门狗、资源自愈、断点续跑、优雅停机、metrics 采样；短时连续运行有多次实测。
缺：跑满 24h 的 `logs/metrics.csv` 内存/句柄趋势。判据：`metrics.csv` 覆盖 ≥24h 且 RSS 无单调上升。
