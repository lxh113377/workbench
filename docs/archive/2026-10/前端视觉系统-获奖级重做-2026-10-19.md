## 0.9 v2 改版：从「安静奢华」到「科技感 HUD」（2026-10-20，老大反馈驱动）

> 老大反馈原话：**「不够有科技感」**。v1 是暖金·安静奢华（克制、精致，但太静态、太"高级灰"），
> v2 转向**冷青·HUD 仪表**：让界面读起来像一台正在运行的仪器，而不是一张漂亮的海报。

### 0.9.1 四项根本改动

| 维度 | v1（安静奢华） | v2（科技感 HUD） |
|---|---|---|
| **色彩** | 暖黑 `#07080a` + 骨白 + 信号橙 `#ff6a3d` | **冷蓝黑 `#04070d`** + 冷白 `#ecf4ff` + **电光青 `#22d3ee`**（副信号紫 `#a78bfa`） |
| **形状** | 圆角卡片 14px | **切角面板**（`clip-path` 12px 斜切）+ 角标 + 描边用 inset 阴影（border 会被 clip 切掉） |
| **光效** | 单层径向辉光 | **多层**：顶部冷极光 + 环境网格 + 卡片扫描线 + 顶栏数据流 + 状态色发光令牌 |
| **动效** | 3 个（呼吸/滑杆/页切换） | **17 个/页**：KPI 错峰入场（10 级延迟）+ 卡片顶缘扫描（错峰 9s）+ 数据流 + 雷达呼吸 |

### 0.9.2 具体手法（都可复算）

1. **冷色体系令牌化**：新增 `--accent-rgb / --warn-rgb / --danger-rgb` 三个 RGB 通道令牌，
   所有半透明色改为 `rgba(var(--accent-rgb),.xx)` —— 换主色只需改一处。
2. **首页 HUD 取景框**：用 `background-image` 的多重 `linear-gradient` 画出**四角 L 形定位标 + 上下边刻度尺**
   （零额外 DOM，绕开首页「禁止新增可见元素」的契约）。
3. **能量核心按钮**：`clip-path` 八边形切角 + 内部 14px 微网格 + 顶部全宽发光线 + 巡游渐变边框（`@property --ang`）。
4. **KPI 读数格**：左上发光线（hover 拉满）+ 右下菱形角标 + 微网格底 + **10 级错峰入场**。
5. **表格数据通道**：表头底缘冷光渐变线 + 行悬停左侧电流条（内阴影扩散）。
6. **顶栏数据流**：一条 38% 宽的冷光沿水平 7s 循环巡游，暗示「系统在运行」。

### 0.9.3 过程中修掉的 3 个自身缺陷（走查抓出）

| 缺陷 | 现象 | 修法 |
|---|---|---|

## 1. 设计系统（替换原「系统默认暗色 + 蓝色渐变按钮」）

### 1.1 色彩：近黑冷灰底 + 唯一信号色

| 令牌 | 值 | 用法 |
|---|---|---|
| `--bg` / `--panel` / `--panel2` | `#07080a` / `#0f1216` / `#14181d` | 三级表面（不做纯黑，保留冷绿灰） |
| `--fg` / `--fg-2` / `--dim` / `--dim-2` | `#f1efe9`（骨白）/ `#cfccc4` / `#98a0aa` / `#7a838f` | 四级文本；`--dim` 对面板对比度 ≈ 7:1 |
| `--accent` | `#ff6a3d`（信号橙） | **唯一高饱和色**，只用于「可操作 / 活跃」 |
| `--accent-2` / `--warn` / `--danger` | `#58e0c0` / `#ffb020` / `#ff5c5c` | 运行 / 警示 / 危险三语义 |

原设计（蓝色 #4f8cff 渐变按钮 + 紫色径向辉光）是典型 AI 默认审美，已整体移除。

### 1.2 字体：DIN 级窄体 × 系统中文黑体

* 展示/数字：`Bahnschrift SemiCondensed → Bahnschrift → Segoe UI Variable Display → 微软雅黑`
  （Bahnschrift 是 Windows 自带的 DIN 级可变窄体，仪表盘的「刻度感」由它承担，零下载）
* 正文：`Segoe UI Variable Text → Segoe UI → 微软雅黑 → PingFang SC`（跨平台回落齐全）
* 等宽：`Cascadia Mono → Consolas`，用于标签、代码、日志

排版规则：卡片标题 = **编号 + 字距拉开的微型大写标签**（`01 执行与开发`），
而不是「大号黑体标题」；KPI 数字用 `tabular-nums` 对齐；正文 1.6 行高、段宽 ≤68ch。

### 1.3 形状与层级

* 1px 发丝线（`rgba(255,255,255,.075)`）承担结构，**不用阴影堆叠**；
* 卡片上缘一圈渐隐反光 + 左上 26px 信号色短杠（悬停才拉满）；
* 唯一的高饱和块 = `.btn.primary`（信号橙渐变 + 内高光），克制到一屏最多一个；
* 所有交互元素统一 34px 高（触屏/窄屏 44px），圆角 7–14px 两档。

### 1.4 动效（三条，全部可 `prefers-reduced-motion` 归零）

| 动效 | 实现 | 时长 |
|---|---|---|
| 开屏「呼吸 + 边框巡游」 | `@property --ang` + `conic-gradient` 旋转 + 内发光呼吸 | 9s / 7s，linear + ease-in-out |
| 页签滑杆 | `.tab::after` `transform:scaleX` | 260ms `cubic-bezier(.2,.72,.24,1)` |
| 页切换 / 按下反馈 | `paneIn` 6px 上浮 + `translateY(1px)` | 340ms / 120ms |

不支持 `@property` 的浏览器：conic 停在 0°，退化成静态渐变边框，**布局不坏**。

## 2. 四个界面的改造

### 2.1 首页（唯一按钮 = 唯一记忆点）

层级由「亮度递减 + 尺度递增」建立：中心按钮（最亮）→ 雷达同心环（132px 环距，向心衰减）
→ 蓝图网格（72px + 18px 双层）→ 胶片颗粒（3.5%，`mix-blend-mode:overlay`）。
宽屏加发丝取景框（≥900px），窄屏去掉以免局促。
按钮态：`idle` 呼吸 / `busy` 快转（3.2s）/ `running` 青绿慢转（14s）/ `paused` 琥珀静止 /
`stopped` 灰边静止 / `error` 红边快转；加载环仍只在该出现时出现（契约未破）。

### 2.2 管理面板

* 顶栏拆成 **命令区（topbar）+ 页面识别区（pagebar）**：pagebar 用 `clamp(26px,3.4vw,40px)`
  的巨大静态标题 + 微型面包屑，给面板「重量」而不靠加卡片；
* 内容区最大宽 1320px 居中，留白 `26px 30px 64px`（≥1600 提到 44px/80px）；
* KPI 从 10 张单列卡变成 `auto-fit minmax(210px,1fr)` 读数面；窄屏两列（原一列会把首屏拉到 2600px）；
* 设置面 `.grid.c2` 固定两列、输入框限宽 560px（原来被 auto-fit 拉成三列、输入框横跨全屏）；
* 审计日志 / 工作目录等长表统一包进 `.table-scroll`（`max-height:min(64vh,680px)`），
  表头 sticky —— 3000px 的日志不再把其它信息挤出视线；
* 「自主运行未启用」从一行小字变成 `.hint-panel` 提示面板（标题 + 四步流程 pill + 开启位置代码）。

### 2.3 模型池

清单表 9 列在桌面收紧行高（`td padding 11px 12px`、序号列等宽），行内操作按钮统一描边小件并在
悬停时染信号橙；窄屏卡片式（`data-label` + `td::before`）保留并换成 12px 圆角卡 + 微底；
页内 `<style>` 只放「池专属」规则，通用件全部走全局（契约测试仍钉得住边界）。

### 2.4 治理控制台

* 新增**首屏状态带 `.gov-hero`**：左侧超大等级字（`clamp(40px,5.2vw,58px)`，按等级染色）+
  结论脚注，右侧 3×2 关键读数格（契约/在履约/合规均分/逾期/预警/采样），结论先行、证据在后；
* 「考核校验」从 7 行长列表改成 **矩阵网格 `.gov-check`**：8 项一屏扫完，PASS/FAIL/未验证
  用左缘色条 + 胶囊标，目标/实际/证据压进 `title`（悬停可读）；
* 三个独立页面共用同一套 topbar/pagebar/卡片/按钮/表格令牌，视觉完全同构。

## 2.5 量化审计（本轮新增：不靠肉眼，全部可复核）

肉眼走查只能发现「明显难看」，发现不了 4.6:1 与 3.9:1 的对比度差别、28px 的可点区域、
11px 微型标签在 390px 下的可读性。所以本轮补了一个**真实浏览器计算样式审计器**
（`tests/ui/design-audit.mjs` + `tests/ui/probes/audit.js`），在 CDP 里逐元素取
`getComputedStyle`，自底向上合成背景算 WCAG 对比度，并测可点尺寸/焦点指示/行长/字号谱。

### 2.5.1 审计器自身先修了一个测量缺陷（重要）

第一版 `bgOf()` 是**自上向下**遍历祖先链的，遇到 `alpha<1` 的层就把父层当不透明 ——
于是卡片 `rgba(255,255,255,.03)` 的半透明底被算成接近纯白，
深色面板上的灰字被误判成 **1.01:1**，一次就报出 28 处「低对比」假阳性。
改为**自底向上逐层 over 合成** + 渐变取色标加权平均后，假阳性全部消失。

> 教训：**读数不可信的审计比没有审计更糟**。任何自动判据先要证明自己能测对——
> 本轮用「已知设计值 #98a0aa on #0f1216 ≈ 5.1:1」当基准校对，改完立即吻合。

### 2.5.2 首轮审计发现的真实缺陷（4 项，已全部修复）

| # | 缺陷 | 审计读数 | 修复 |
|---|---|---|---|
| 1 | 类型标度失控：CSS 里有 **18 个离散字号**（10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14…） | 字号谱统计 | 收敛为 **9 档**，下限提到 11px（原 10px 在 390px 下不可读），并固化为 `:root` 语义令牌 `--fs-micro/mono/small/base/lead/kpi` |
| 2 | 首页后门「·」对比度 **1:1** 且键盘聚焦无指示 | `lowContrast` + `focus 1/2` | 虽是有意的 `color:transparent`，但聚焦时必须给锚点：补 `.home-admin:focus-visible` 信号色光环；审计器同时排除「故意不可见」元素，避免把设计意图判成缺陷 |
| 3 | 可点目标偏小：`.btn.sm` 28px、模型池行内 ↑↓ 按钮 **24px**、复选框 **15×13px** | `smallTargets` | `.btn.sm` 28→36；池内按钮 24→**32px**（触屏档仍 44）；复选框控件 15→18 并用 `label:has()` 扩到 32px 命中区 |

### 2.5.4 CLS 修复（本轮最后一项）

页签切换时 pane 是「先空后填」：`renderQueue` 等异步取数，空 pane 高度接近 0，
数据到达后高度突变，把下方元素整体推走。审计实测 3 页 CLS = **0.025**（queue / logs / settings）。

修法两条（都不牺牲动效质感）：
1. 激活 pane 给 `min-height:min(46vh,420px)`，让「空 → 满」的高度变化发生在预留空间内；
2. `paneIn` 从「位移 6px」改为**纯透明度**——位移本身就会产生 layout shift 贡献。

修后 17 页 CLS 全部归零。

### 3.2 本轮修掉的两个「假红」陷阱（判据/探针自身缺陷）

   `TestLoadingRingOnlyVisibleWhenActuallyLoading` / `TestResponsiveCSSContract` 当场判红 ——
   说明契约层有效：视觉可以换，但「状态反馈必须诚实」「按钮必须连续缩放」不许退化。
