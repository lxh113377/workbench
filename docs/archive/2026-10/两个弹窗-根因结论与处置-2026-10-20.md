# 两个桌面弹窗 —— 根因结论与处置（2026-10-20 07:20）

老大反馈「这两个弹窗怎么搞的一直蹦出来」。经 OCR 取证 + 窗口级监控（EnumWindows 100ms 采样）+
受控复现，两条链路均已定位、修复并验证。

## 弹窗 A：PowerShell 控制台窗（keepalive 日志刷屏）

**取证**（OCR 微信图片_4382）：
```
keepalive: D:workdesktopdistworkbench 进程不在，拉起
keepalive: 经 lib-silent-launch 拉起 pid=34884
keepalive: [fix-patch] already fixed
```

**根因**：计划任务 `WorkBenchKeepAlive`（每分钟）直接以 `powershell.exe -WindowStyle Hidden`
执行 keepalive.ps1。Windows 11 的默认终端是 Windows Terminal，计划任务上下文里
`-WindowStyle Hidden` 只作用于 conhost 分配的窗口，**Windows Terminal 宿主窗不受它控制**，
于是每分钟弹一个 Terminal 窗。

**对照实验**（同形状计划任务，100ms 窗口采样）：

| 启动方式 | 新可见窗口 |
|---|---|
| powershell -WindowStyle Hidden（原） | 2-3（Terminal 窗） |
| wscript //B → VBS sh.Run(...,0) | 2（仍有残留路径） |
| pythonw → Popen(CREATE_NO_WINDOW) | 2 |
| cmd start "" /min | 3 |
| **conhost --headless powershell** | **0** |

**处置**：任务动作改为
`C:\Windows\System32\conhost.exe --headless powershell.exe <原参数>`。
原任务定义已备份到 `xtmp/WorkBenchKeepAlive.xml.bak-20261020`。

**验证**（2026-10-20 07:03）：手动触发 + 6 分钟持续观测跨多个 keepalive 周期，
新可见窗口 = 0；keepalive 功能正常（LastTaskResult=0，生产实例健在，面板 HTTP 200）。

## 弹窗 B：Edge 显示「127.0.0.1 拒绝连接 / 无法访问此页面」

**取证**（OCR 微信图片_4383）：`127.0.0.1 拒绝连接 ERR_CONNECTION_REFUSED`。

**根因**（两层，均有实锤）：

1. **产品缺陷（已在源码+产物修复）**：旧版「已在运行」分支用端口顺延扫描定位面板，
   会把浏览器指向相邻的压测/探针端口；探针一死就成了死端口窗口（ERR_CONNECTION_REFUSED）。
   现产物已含 `resolveRunningPanelURL`（只认 runtime/panel.url + HTTP 存活校验）+
   `--silent` 全分支覆盖（main.go:143-168，部署件二进制含该标记，实测输出
   `工作台已在运行：http://127.0.0.1:17890/` 且无弹窗）。
2. **残留窗口复活机制**：Edge 以 `--no-startup-window` 自启（开机 Run 键）后仍会
   恢复上次的 app-mode 会话条目（Sessions\Apps_*.dat 中存有 http://127.0.0.1:17890/ 等）。
   端口活着时显示正常面板；指向已死探针端口（17931/17957）时就是"拒绝连接"死窗。
   今晨 06:58:57 Edge 重启即恢复出一个指向 17890 的 app 窗。

**验证**（2026-10-20 07:05-07:08）：杀掉生产实例 → keepalive 一分钟内静默拉起
（pid=13668，`--silent`）→ 3 分钟观测 **0 个新可见窗口** → 面板恢复 HTTP 200。
非静默双击路径不受影响（隔离探针实例输出 `已打开面板：http://127.0.0.1:17891/`）。

## 仍在发生的干扰源（非产品缺陷，需 Lead 配合）

07:15:26 有一个 Lead 会话（DSH Desktop pid=36312）执行了
`Start-Process dist\workbench.exe`（**不带 --silent**）——这会在桌面弹面板窗口。
这是 Lead 侧验收命令的问题，不是产品缺陷；产物对不带 --silent 的启动弹面板是**设计行为**
（用户双击快捷方式就该弹面板）。请 Lead 的验收脚本统一加 `--silent`。

同理，Lead 的 ui-probe 实例（--ui-probe --port 17931）用 headless Edge 跑门禁本身不弹窗，
但探针端口死后，Edge 会话恢复可能再show出指向该端口的死窗——出现时直接关掉那个 Edge 窗即可，
根因（产品侧）已修。

## 复验入口

- 任务动作：`(Get-ScheduledTask WorkBenchKeepAlive).Actions` 应为 conhost --headless 包装
- 静默守护：杀 dist 实例 → 1 分钟内回来 → 全程无桌面弹窗
- 死端口窗口：不应再由产品自身产生；若 Edge 恢复出旧窗口，指向的端口要么 200 要么手动关闭
