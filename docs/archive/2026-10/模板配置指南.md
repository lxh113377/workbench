# 任务模板配置指南

> 模板决定工作台"每天在产出什么"。24 条内置模板开箱即用，也支持完全自定义。

---

## 一、模板是什么

一个模板 = 一类可持续产出的任务"配方"。它包含三部分信息：

1. **怎么生成任务**（Prompt 模板 + 占位符）
2. **怎么评估这个任务值不值得做**（价值先验 / 成本先验 / 优先级）
3. **产出后往哪延伸**（后继模板链 + 深度 + 扇出）

---

## 二、字段全表

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 英文唯一标识（如 `my-report`）。用户模板不能与内置 ID 重复 |
| `name` | string | ✅ | 显示名称，如「深度长文」 |
| `domain` | string | ✅ | 领域：`content` / `code` / `knowledge` / `data` / `solution` / `report` |
| `description` | string | | 一句话说明这个模板产出什么 |
| `promptTemplate` | string | ✅ | Prompt 模板，**必须含 `{topic}`** |
| `priorityWeight` | int 1-5 | ✅ | 调度优先级。5 = 最先跑 |
| `valuePrior` | 0-100 | ✅ | 价值先验分。它占三维评估中「价值」维度的 60% |
| `costPrior` | 0-100 | | 成本先验（越大越贵）。不填默认 50 |
| `cooldownMinutes` | int | | 同一模板的最小间隔（分钟）。不填 60 |
| `diversityGroup` | string | | 多样性分组，用于避免同类扎堆。默认等于 domain |
| `enabled` | bool | | 是否启用。禁用后不再被采样 |
| `outputSpec.format` | string | | `md`（默认）/ `txt` |
| `outputSpec.sections` | string[] | | 期望的章节名。自评时会对照检查 |
| `outputSpec.minWords` | int | | 期望最少字数。自评低于此视为严重不足 |
| `outputSpec.minBytes` | int | | 期望最少字节数 |
| `params.modelTier` | string | | `quality` / `balanced`（默认）/ `fast`。影响选哪个模型 |
| `params.maxMinutes` | int | | 单任务超时（分钟）。默认 30 |
| `params.outputFormat` | string | | 同 outputSpec.format |
| `params.webAllowed` | bool | | 是否允许联网（影响可行性评分） |
| `params.tags` | string[] | | 标签，会写进任务的 tags |
| `chain.successorTemplates` | string[] | | 后继模板 ID 列表（任务完成后自动生成的下游任务） |
| `chain.maxDepth` | int 1-20 | | 这条链最多延伸几层 |
| `chain.fanout` | int 0-4 | | 每个任务最多分裂出几个后继 |

---

## 三、可用占位符

| 占位符 | 含义 | 说明 |
|---|---|---|
| `{topic}` | **必填** | 主题。由工作台从对应领域的选题池里挑选，或从父任务继承 |
| `{words}` | 期望字数 | 自动取 `outputSpec.minWords` |
| `{context}` | 前序上下文 | 链式任务时自动注入父任务的产出摘要 + 自评标签 + 不足点 |
| `{date}` | 当前日期 | `YYYY-MM-DD` |
| `{prev}` | 前序结论 | 父任务 summary 的前 400 字符 |

> 写其他占位符（如 `{foo}`）会在保存时被拒绝 —— 这是刻意设计，避免把非法字符带进 Prompt。

## 四、6 个领域与内置模板一览

| 领域 | 内置模板（各 4 条） |
|---|---|
| **content 内容创作** | 深度长文 / 要点卡片化 / 口播脚本 / 常见问题解答集 |
| **code 代码生成** | 实用小工具 / 代码审查报告 / 代码片段库 / 测试方案设计 |
| **knowledge 知识整理** | 知识地图 / 术语表 / 方案对比 / 实操手册 |
| **data 数据处理** | 数据分析报告 / 数据清洗规则 / 指标体系设计 / SQL 实战手册 |
| **solution 方案撰写** | 方案设计 / 落地上线清单 / 风险评估 / SOP 流程文档 |
| **report 报告生成** | 阶段性报告 / 调研报告 / 对标分析 / 决策摘要 |

内置模板的链式关系（举例）：
```
深度长文 ──► 要点卡片化 ──► 口播脚本
    └─────► 口播脚本
知识地图 ──► 术语表 / 实操手册
方案设计 ──► 落地上线清单
实用小工具 ──► 代码审查报告
```

## 五、写一个好模板的 5 条原则

### 1. Prompt 要"能直接执行"，不要"能讨论"
❌ `请分析一下 {topic}`
✅ `请围绕「{topic}」产出 15 条常见问题与解答，每条答案必须给出具体做法而非空话，输出 Markdown。`

### 2. 明确产出结构
把 `outputSpec.sections` 和 Prompt 里的章节要求对齐。自评会对照检查，结构越明确评分越稳。

### 3. valuePrior 要有区分度
- 90-100：高价值、有沉淀（深度长文、方案设计、调研报告）
- 70-85：中等价值（清单、FAQ、脚本）
- 40-60：辅助性产出（术语表、片段库）

全设 90 会让评估失去筛选意义。

### 4. 用链式关系做递进
一个孤立的模板只能产出单点内容；配了 `successorTemplates` 才能形成"越挖越深"的链。

例：调研报告 → 对标分析 → 决策摘要 → 落地上线清单

### 5. 控制成本
`costPrior` 高 + `maxMinutes` 长 = 昂贵任务。别让 24 条模板全是重任务，否则并发槽会被长期占满。

## 六、两个完整示例

### 示例 1：行业周报（轻量高频）

```json
{
  "id": "industry-weekly",
  "name": "行业周报",
  "domain": "report",
  "description": "每周输出一份目标行业的动态摘要与观点",
  "promptTemplate": "请产出关于「{topic}」的行业周报，约 800 字。包含：本周关键信号（3-5 条）、背后的结构性变化、对我们意味着什么、下周值得关注的点。结论先行，不要罗列新闻。输出 Markdown。",
  "priorityWeight": 4,
  "valuePrior": 82,
  "costPrior": 35,
  "cooldownMinutes": 1440,
  "diversityGroup": "report",
  "enabled": true,
  "outputSpec": { "format": "md", "sections": ["关键信号", "结构变化", "影响", "关注点"], "minWords": 800, "minBytes": 2000 },
  "params": { "modelTier": "balanced", "maxMinutes": 25, "outputFormat": "md", "webAllowed": false, "tags": ["周报"] },
  "chain": { "successorTemplates": ["report-executive"], "maxDepth": 2, "fanout": 1 }
}
```

### 示例 2：面试题拆解（深挖型）

```json
{
  "id": "interview-drill",
  "name": "面试题拆解",
  "domain": "knowledge",
  "description": "把一个技术主题拆成面试题 + 标准答案 + 追问链",
  "promptTemplate": "请围绕「{topic}」设计 10 道由浅入深的面试题。每题给：考察点、标准答案要点、常见错误回答、以及一个追问。输出 Markdown。参考前序内容：\n{context}",
  "priorityWeight": 3,
  "valuePrior": 78,
  "costPrior": 40,
  "cooldownMinutes": 120,
  "diversityGroup": "knowledge",
  "enabled": true,
  "outputSpec": { "format": "md", "sections": ["题目"], "minWords": 900, "minBytes": 2200 },
  "params": { "modelTier": "quality", "maxMinutes": 35, "outputFormat": "md", "webAllowed": false, "tags": ["面试", "深挖"] },
  "chain": { "successorTemplates": ["knowledge-glossary"], "maxDepth": 4, "fanout": 2 }
}
```

## 七、导入 / 导出

- 导出：面板 → 模板 → 「导出模板」→ 得到 `templates.json`
- 导入：直接 `POST /api/templates`，body 为模板数组；校验不通过的条目会被跳过（不会污染模板池）
- 恢复默认：面板 → 模板 → 「恢复默认」→ 清除所有自定义模板，回到 24 条内置

---

## 八、校验规则（保存时强制）

保存模板时工作台会检查：

1. `id` 非空
2. `name` 非空
3. `priorityWeight` ∈ [1,5]
4. `valuePrior` / `costPrior` ∈ [0,100]
5. `chain.maxDepth` ∈ [1,20]，`chain.fanout` ∈ [0,4]
6. `promptTemplate` 非空且**包含 `{topic}`**
7. 占位符只能是 `{topic} {words} {context} {date} {prev}`，出现其他会报错并说明

任何一条不过 → 拒绝保存并返回具体原因。
