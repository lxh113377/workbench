## 1. 【新·生产缺陷】workspace 功能的 executor 接线在恢复中丢失

| 判据 | 结果 |
|---|---|
| executor.Runner 的 allowAll 字段 | **0 次出现**（结构体只剩 cfg / hooks / layout） |
| SetAllowAll() / AllowAll() | **实现中不存在** |
| SetWorkspaceContext() / workspaceContext() | **实现中不存在** |
| task.WorkRoot 的使用 | **不存在** |
| executor/pure.go 的 BuildArgsWithPatches / SandboxOverlayYAML | **仍在**（YES） |

### 后果（静默失效，非报错）

engine.setRunnerAllowAll 用 type switch 探测：

```
switch x := r.(type) {
case interface{ SetAllowAll(bool) }:        // executor 没有这个方法 => 不匹配
case interface{ Inner() RunnerContract }:   // FailoverRunner 有 => 下探
return                                       // 最终静默 return
```

=> external 模式下**运行层沙箱放行补丁永不生效**，且因为无报错，本机 project 模式测不出。
=> 与 workspace 死锁同类：**静默失效型缺陷**（比崩溃更难发现）。

### 处置

把 executor 侧这三件补回（源码可从本会话早前提交 12ac84e 或 src-backup/wsfix 对应实现取）：
1. Runner 加 allowAll bool + SetAllowAll / AllowAll；
2. Runner 加 wsContext func() string + SetWorkspaceContext / workspaceContext；
3. executor.run 里：cwd 用 task.WorkRoot（external 时）、追加 sandbox 补丁、prompt 注入上下文。
