# 缺陷报告：验收命令被反斜杠转义污染导致无限返工（2026-10-19 15:2X · ds 端）

## 现象
现场 13/23 个任务触发过返工（最大 3 轮）。一类失败长这样：

```
#1 `pwsh -NoProfile -Command "if (Test-Path action_plan.md) { exit 0 } else { exit 1 }"`
退出码 1（期望 0）：\if: 术语 '\if' 不会被识别为 cmdlet、函数、脚本文件或可执行程序的名称。
```

注意 stderr 里的 `\if` —— 命令被污染了。

## 根因（容器内实测复现，三行证据）

```
input : pwsh -NoProfile -Command \\"if (Test-Path a.md) { exit 0 } else { exit 1 }\\"
argv  : ["pwsh" "-NoProfile" "-Command" "\\if (Test-Path a.md) { exit 0 } else { exit 1 }\\"]
```

**`splitCommand`（workbench/internal/verify/verify.go:182-220）的引号状态机不识别
`\"` 转义序列**：

```go
case r == '\'' || r == '"':
    quote = r          // ← 把 " 当引号开始
default:
    cur.WriteRune(r)   // ← 把前一个 \ 当普通字符写进 token
```

于是 `\"` 被切成「一个字面 `\` + 一次引号开合」，`\` 残留进 argv，
pwsh 收到 `\if ...` 直接报「术语不识别」。

## 触发条件（为什么会发生）
模型在 ARTIFACTS manifest 的 `cmd` 字段里写 `pwsh -NoProfile -Command "..."` 时，
按 JSON 规则本应写 `\"`；若模型写成 `\\"`（双反斜杠，常见于"过度转义"），
JSON 反转义后就剩下一个字面 `\` 紧跟引号 ⇒ 命中本缺陷。

## 影响
- 该任务的真实验收**永远不可能通过**（命令本身畸形）⇒ 反复返工直到 repairRounds 耗尽；
- 浪费额度与时间，且把"模型能力问题"误报成"产物不可运行"；
- 现场返工率 57%（13/23）里有一部分是这个问题，不是模型不听话。

## 修复建议（Lead 定，最小改动）
在 `splitCommand` 的 default 分支前加反斜杠逃逸处理：

```go
case r == '\\' && quote != '\'':
    // Windows/POSIX 通用：反斜杠转义下一个字符（含引号自身）
    escaped = true
    continue
...
if escaped { cur.WriteRune(r); escaped = false; continue }
```

或在 `runOne` 里对 `c.Cmd` 先做一次 `strings.ReplaceAll(s, "\\\"", "\"")` 归一化
（把残留的 `\"` 还原成 `"`）—— 一行，风险更低。

**回归测试已备好**（本报告同目录 `_split_repro` 下有最小复现；
正确行为：`argv[3]` 应等于 `if (Test-Path a.md) { exit 0 } else { exit 1 }`，不以反斜杠开头）。
