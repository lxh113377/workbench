# 后台一堆「个人AI工作台」：根因、修复与防再犯（2026-10-20）

> 现场：老大截图任务管理器「后台进程」里有 ~24 个「个人AI工作台」，单进程仅 8–24MB。
> 目标：查原因 → 防再犯 → 修好。本文是三条的取证记录（全部为本机实测读数）。

## 一、根因（四条互相独立的拉起链，谁都不负责回收）

单实例锁是**按 runtime 目录**做的（`internal/single` + `layout.RuntimeDir`，runtime 由 EXE 所在目录推导）。
只要 `--dir` 不同就是不同"实例域"，锁各管各的。而机器上有四条会不断拉起 EXE 的路径：

| # | 拉起链 | 证据 |
|---|---|---|
| ① | 开机自启 `HKCU\...\Run\PersonalWorkbench = "D:\workdesktop\dist\workbench.exe" --silent` | 注册表实测在册 |
| ② | 计划任务 `WorkBenchKeepAlive`（每 1 分钟）→ `tests\keepalive.ps1` → Win32_Process.Create 拉起 `--silent` | 任务实测 Running/Ready，最近一次 22:38:29 result=0 |
| ③ | 进程内 supervisor.SelfHeal：`os.Executable()` 再拉一份 `--silent` | `workbench/internal/supervisor/supervisor.go:220-232` |
| ④ | 探针/验收/压测装置：`--ui-probe` / `--soak` / `--acceptance` 各自用独立 `--dir` 起实例 | `tests/check_perf.ps1`、`dist/ui-shots/*`、`runtime/soak-24h*` 留痕 |

**关键放大因素**：②③ 走 `Win32_Process.Create`，子进程的 PPID 落在常驻的 WmiPrvSE 上，
"父进程死了就退出"这条自然兜底**彻底失效** —— 进程可以无限期活着。
而整套系统**没有任何一处**枚举"机器上现在有几个实例"。`keepalive.ps1` 只看
`Get-WorkbenchProc | Select-Object -First 1`（至少有一个在跑），从不判重、从不清理。于是只增不减。

现场取证：20:30 截图时 ~24 个家族进程，而生产实例 16:57 就已被用户退出
（`runtime\user-quit.flag` 内容 `user quit at 1792486662010`，16:57:42）。**全是孤儿。**

## 二、修好（当场）

1. 清掉全部孤儿实例：`tests\instance_guard.ps1 -Apply`（本轮实测清理 pid 7440 / 29596,32536,11572 / 21028,19380,19960 / 6388,34352,13824,44640,44904，每次留痕到 `runtime\instance-guard.log`）。
2. 换成**当前源码**构建的产物（现场还有另一个独立缺陷：dist 里 21:52 的产物是**旧树**构建，服务的是旧首页 —— 详见 §四）。
3. 起回**恰好 1 个**生产实例，且按老大要求**无 GUI**：`"D:\workdesktop\dist\workbench.exe" --silent`
   （终态 pid 41448，`mainWindowHandle=0`、无托盘窗口、`server.openBrowser=false`），
   面板只走 HTTP：`http://127.0.0.1:17890/`（实测 200、len=1299、首页已是新版）。

## 三、防再犯（三道闸，全部机器可判）

### 闸 1：新增 `tests\instance_guard.ps1`（机器级实例盘点 + 有界回收）
家族判据 = 产物 `ProductName = 个人AI工作台`（含 wb-*.exe 之类改名副本）。
五条裁决，幂等、零人工交互、默认只报告（`-Apply` 才动手）：

| 裁决 | 规则 |
|---|---|
| A | 生产实例最多 1 个（优先留 `runtime\workbench.lock` 登记的 pid） |
| B | `runtime\user-quit.flag` 在册（用户显式退出）且进程 age > max(宽限, 300s) → 回收 |
| C | 探针实例超过自己声明的 `--seconds` 预算 + 宽限 → 回收（违约未退） |
| D | 探针无预算且 age > TTL(10min) → 回收 |
| **E** | **全局硬上限 MaxInstances=6**：家族实例超限时从最老探针起回收（绝不回收生产实例） |
| F | 探针父进程已死且过宽限 → 回收（Win32_Process.Create 场景不常命中，留作兜底） |

退出码：0=干净 / 1=有动作（报告=FOUND，`-Apply`=REAPED）。

### 闸 2：接入既有守护心跳
`tests\keepalive.ps1` 里 `Repair-IntegrityLabel` 之后调用
`instance_guard.ps1 -Apply -Quiet`，异常只打印不抛出。
`WorkBenchKeepAlive` 计划任务本来就每分钟一跳，于是**每分钟**做一次机器级盘点。

### 闸 3：首页契约门禁进构建链
新增 `tests\check_homepage.ps1`，并在 `setup\build.ps1` 的"6/6 校验产物"里调用。
三态：PASS / FAIL / UNVERIFIED(rc=2)。判据见 §四。

## 四、附带修掉的第二个现场缺陷：打开的是旧页面

老大第二轮反馈「打开的是旧的页面,已经有新的了」。取证：

- `dist\workbench.exe`（21:52，9,650,176B）字节里：`home-badge=True` / `home-entries=False` / `UI_PROBE_READY=False`
- 当前源码 `workbench/internal/web/html.go`：`home-badge=False` / `home-entries=True`
- `git HEAD` 的 html.go：`home-badge=True`（旧页）—— 工作区的新页尚未提交
- `src-backup` / `_recovery` 的 html.go 也是旧页，且**没有 ui_probe.go**
- 实测从 `src-backup\workbench` `go build` 出来的产物：`oldUI=True / probe=False`（与 21:52 产物同族）

⇒ 21:52 那份产物是**从旧树构建后覆盖进来的**，并且丢了 `--ui-probe` 分支。
后果是"打开旧页面"+"探针静默回落成 GUI"两件事同时发生。
当时的构建门禁只查 PE 子系统（GUI/不弹窗）+ 体积，**没有任何一条判据看页面内容**。

修复：
1. 从当前工作区源码重建（`-trimpath -ldflags "-s -w -H=windowsgui -X main.version=1.2.0 ..."`），
   产物 10,063,360B，subsystem=2(GUI)，`home-entries=True / home-badge=False / UI_PROBE_READY=True`，
   实测 HTTP 首页为新版（含「管理面板/模型池/治理」三个入口）。
2. 刷新 `dist\SHA256SUMS`（新 sha256 = D2D1989E7A3F64A6657717F3BB834D16F467EAAF4A04EDC2EC455E51E7798611）。
3. 新增首页契约门禁（见闸 3），三条判据：
   - 产物必须含新页锚点 `home-entries`，不得含旧页锚点 `home-badge`
   - 产物必须含 `UI_PROBE_READY`（否则 `--ui-probe` 静默回落成 GUI）
   - 起真探针抓 HTTP 首页，断言响应同为新页（防"字节里有、路由没用上"）

三态自证（实测）：新产物 PASS rc=0 / 旧产物 FAIL rc=1（3 条全红）/ 产物不存在 UNVERIFIED rc=2。

## 六、仍然存在的已知边界（不虚报）

- **闸 1 只回收"能被盘点到的"实例**：若有人把 EXE 复制成 `ProductName` 被改过的文件，家族判据会失配。
- **MaxInstances=6 是机器级总上限**，不是"每个探针都合法"——同时跑 >6 个并行探针会被裁决回收，
  并行压测需显式抬 `-MaxInstances`。
- **B 的宽限取 300s**：产品只在 `Engine.Start` 时清 `user-quit.flag`，
  用户双击拉起后若 5 分钟内都没点「开始」，该实例会被判残留回收。
- ③ SelfHeal 与 ② 的拉起语义未改（它们本身是 7×24 的正确设计），本次是在其**外面**加了回收位；
  若今后新增第五条拉起链，需同步扩 `$ProbePattern` / 家族判据。
