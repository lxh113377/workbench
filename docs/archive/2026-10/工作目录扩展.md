# AI 开发工作目录扩展（外部目录模式）

> 版本：v1.3.0 ｜ 日期：2026-10-19 ｜ 对应需求：突破"仅能在项目默认文件夹内开发"的限制
> 代码：${bt}workbench/internal/workspace/${bt}（护栏与上下文）｜ 装配：engine / executor / web / cmd

## 1. 要解决什么

改造前任务的工作目录硬编码为 ${bt}<DataRoot>/tasks/<id>/workspace${bt}：模型产出的文件只能落在工作台自己的
沙箱目录里，无法在用户真实的项目文件夹中创建文件、编辑代码、跑构建。本功能新增**可选的**外部目录
模式，让 AI 直接以用户指定的任意本地文件夹作为工作目录，同时不改变默认行为。

## 2. 两种模式（默认兼容 + 可选新增）

| 模式 | 任务工作目录 | DSH 运行层沙箱 | 适用 |
|---|---|---|---|
| ${bt}project${bt}（默认） | ${bt}<DataRoot>/tasks/<id>/workspace${bt} | ${bt}sandboxPolicy${bt} 默认（read-only + 升权审批） | 与改造前**逐字节一致**，存量安装升级后行为不变 |
| ${bt}external${bt}（新增） | 用户选定的绝对目录 | 追加 ${bt}--patch${bt} 把 ${bt}sandboxPolicy.defaultMode${bt} 设为 ${bt}danger-full-access${bt} | 用户要求 AI 在自己项目里开发 |

为什么 external 必须放开 DSH 沙箱：DSH 的 fs 沙箱边界由 **session cwd 推导的 workspace** 决定，
工作台把子进程 cwd 指向用户目录并不能扩大 DSH 的写入白名单（实测 ${bt}dsh-fs-sandbox${bt} 只认
${bt}policy.workspaceRoot${bt}）。因此运行层必须放开，作用域限制改由**工作台自己的护栏**承担。

## 3. 路径管理模块（${bt}internal/workspace${bt}）

| 能力 | 函数 | 说明 |
|---|---|---|
| 目录校验 | ${bt}Manager.Validate${bt} | 绝对路径 → 存在 → 是目录 → 非系统目录 → 与工作台无重叠 → 可读 → **真实写探针** → 统计入口 |
| 写目标解析 | ${bt}Manager.ResolveWrite${bt} | 归一化 + 软链接解析（${bt}evalExisting${bt}）+ 包含性判定，越界抛错并审计 |
| 读目标解析 | ${bt}Manager.ResolveRead${bt} | 同上，额外允许数据根只读与 ${bt}AllowedReadRoots${bt} |
| 包含性判定 | ${bt}IsWithin${bt} | 大小写不敏感（Windows）、按分隔符边界比较（${bt}C:\foo${bt} 不匹配 ${bt}C:\foobar${bt}） |
| 上下文采集 | ${bt}BuildContext${bt} / ${bt}PromptBlock${bt} | 文件树 + 关键文件（README/go.mod/package.json…），带文件数/单文件/总字节三重上限 |
| 目录选择器 | ${bt}Browse${bt} | 只列目录不读内容，支持盘符列表与父目录回退 |
| 审计 | ${bt}AuditLog${bt} | 每次允许/拒绝追加 ${bt}workspace-audit.jsonl${bt}，坏行跳过 |

### 3.1 硬性拒绝清单（任何模式）

- 磁盘根（${bt}C:\${bt}）、系统目录（Windows / Program Files / ProgramData / System32…）
- 用户主目录**本身**（允许其子目录）
- 工作台自身目录（项目根及其子目录、数据根）——防 AI 改到自己
- 含 ${bt}..${bt} 逃逸、相对路径、软链接指向外部的任何写入目标

### 3.2 授权边界（需求 4 的判据）

1. external 模式下**写**只允许落在用户选定目录内；其余一律 ${bt}ResolveWrite${bt} 拒绝并写审计。
2. 产品落盘链路（${bt}materializeArtifacts${bt}）逐个文件过护栏；有任一被拒 → 任务直接判 degraded，
   不会"少写了文件还报成功"。
3. 读允许：用户目录 + 数据根（成品/配置）+ 显式配置的额外只读根。
4. 所有裁决可在面板「工作目录 → 访问审计」与 ${bt}--workspace status${bt} 复核。

## 5. API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | ${bt}/api/workspace${bt} | 模式/根/最近校验/文件树/审计摘要 |
| POST | ${bt}/api/workspace/validate${bt} | 只校验不落配置（返回原因与建议） |
| POST | ${bt}/api/workspace/select${bt} | 校验并切换为外部目录（唯一写入口） |
| POST | ${bt}/api/workspace/reset${bt} | 切回项目模式（保留上次目录） |
| GET | ${bt}/api/workspace/browse?path=${bt} | 目录选择器（只列目录） |
| GET | ${bt}/api/workspace/audit?tail=${bt} | 路径裁决审计明细 |

## 6. 验收（对应需求 5）

- ${bt}go test ./internal/workspace/${bt}：22 个用例覆盖边界（前缀同形、${bt}..${bt}、软链接逃逸、系统目录、盘符根、
  空/相对/不存在/文件、写探针残留、上下文截断、审计坏行、快照）
- ${bt}go test ./internal/web -run TestWorkspace${bt}：HTTP 全链（校验→切换→失败不污染→审计→切回）+ 页签可发现性
- ${bt}tests/e2e_workspace.ps1${bt}：真实二进制端到端 —— 选目录→跑任务→文件落在用户目录→原数据目录零污染→切回
- 项目门禁 ${bt}python eval/governance_gate.py${bt}：vet + test + 治理 CLI 全绿

## 7. 回滚

- 面板/CLI 一次 ${bt}reset${bt} 即回项目模式（配置仍在 config.json，可随时切回）；
- 也可直接改 ${bt}workbench-output/config.json${bt} 的 ${bt}workspace.mode${bt} 为 ${bt}project${bt}；
- 代码层：新增文件独立在 ${bt}internal/workspace/${bt}，装配点均为"零值即旧行为"，删除字段不破坏存量数据。
