# 子页面被挡住 — 根因与修复（2026-10-20 · 二轮）

> 老大反馈原话：**「除了总览界面没问题，任务、产出、模板、设施（设置）子页面都被挡住了」**。
> 结论先说：**这不是错觉，也不是浏览器缓存** —— 是导航区在窄视口下吃掉了大半屏高度，
> 而总览首屏恰好是 KPI 数字、能露出一点，其它四页首屏是卡片标题区，几乎全被推到屏幕外。

## 1. 现场还原（先量后改）

老大截图窗口 **1040×613 物理像素**。这台机器屏幕 DPI 缩放 **175%**（`devicePixelRatio = 1.75`，
屏幕物理 1920×1200 报成 1463×914）。所以页面真实 **CSS 视口只有 594×350**。

在 594×350 下实测（修复前 v1.3.2）：

| 指标 | 读数 |
|---|---|
| 顶栏外层 `.topbar-shell` 高度 | **193px** |
| 其中页签条 | 46px |
| 导航区占总视口 | **239 / 350 = 68%** |
| 子页内容可见高度 | **99px**（只剩不到三成） |

这就是「被挡住」的真相：不是元素被上层遮住（`elementFromPoint` 全部命中 pane 内部），
而是**内容被导航区挤到了视口之外**。总览页首屏是 4 个 KPI 数字（矮），能露出来；
其余四页首屏是卡片标题 + 说明（高），看起来就像「一片空白 / 被挡」。

## 2. 修法

### 2.1 窄屏导航区瘦身（主修）

`@media (max-width:720px)` 内重做排版，从「三行堆叠」改成「紧凑一行 + 小标题」：

| 项 | 改前 | 改后 |
|---|---|---|
| 顶栏布局 | `flex-wrap:wrap`（品牌独占一行、状态独占一行、按钮再一行） | `nowrap` 单行：色块 + 状态 + 按钮 |
| 品牌 | 整行 120px+ 文字 | 只留 9px 色块（`font-size:0`，保留 `class="brand"` 契约） |
| 状态行 | 独占一行 | 与按钮同排，11px |
| 页面标题 | `clamp(22px,6.4vw,30px)` → 实测 30px | **15px** |
| 页签高度 | 44~46px | **38px** |
| 导航总高 | 239px | **78px**（-67%） |
| 内容可见 | 99px | **222px（+124%）** |

### 2.2 顺手修掉两个连带缺陷

1. **`pointer:coarse` 误伤桌面窄窗口**：原规则写成
   `@media (pointer:coarse), (max-width:720px)` —— 把「窗口窄」当成「手指触屏」，
   桌面用户把窗口拖窄时页签被强制 44px。已拆开：只有真触屏设备才 44px。
2. **模型池顶栏 4 个按钮把页面撑宽 18px**：我给 `.topactions` 加了 `nowrap` 后，
   390px 下「同步/探测/刷新/更多」撑到 274px，`scrollWidth=408 > clientWidth=390`。
   改为 `flex-wrap:wrap + min-width:0`，按钮自身保持 nowrap。实测 390 下 `overflowX=0`。

## 3. 判据（这次补的是真闸门）

新增 `pane` 契约（`tests/ui/probes/pane_geometry.js` + `assertions.mjs` + `cdp_probe.mjs`）：
逐页签点开，量三件事 —— ① 首个内容块是否钻进导航区（`overlap ≤ 1px`）；
② 页签条是否被压扁（`tabsHeight ≥ 30`）；③ **导航区占视口比例 `navRatio ≤ 45%`**。

门禁用例 **20 → 23**，新增三档视口：
- `pane-geometry` 1440×900（桌面）
- `pane-geometry-narrow` 1040×613（用户窗口的物理尺寸）
- `pane-geometry-realwindow` **594×350（用户窗口的 CSS 尺寸，即问题现场）**

### 3.1 判据有效性反证（双向都验了）

| 被测版本 | 判定 | 关键读数 |
|---|---|---|
| 修复前 v1.3.2 | **FAIL**（23 例中 2 例红） | `navRatio=55.1`（>45 上限）；1040 档 `panes[3].paneTextLen=0` |
| 修复后 v1.3.3 | **PASS** 23/23 | `navRatio=22.3%`；五页 `overlap=0`、`visible=222px`、文本全非空 |

## 6. 教训

**「用户说被挡住」不等于「元素被遮挡」**。我先按「查 z-index / 查遮挡」的思路查了两轮都是绿的，
因为 `elementFromPoint` 全都命中正确元素。真正的判据是**几何比例**：内容可见高度 / 视口高度。
以后遇到「看不到 / 被挡住 / 显示不全」这类反馈，第一步应该量**可见比例**，而不是查层叠。
