# 缺陷报告：同目标豁免失效导致自主闭环死锁（2026-10-19 19:5X · ds 端，已应急解除）

## 现象
自主闭环完全卡死：同一个任务被连续创建 **187 次**、每次都被「与最近任务完全重复」拒绝，
零产出。WAL 每 3 秒涨两条（洪水）。

## 根因（代码级，一行缺失）
`internal/evaluate/evaluate.go`：

- `recentItem` 有 `GoalID` 字段（第 29 行）；
- `sameGoal()` 豁免逻辑已实现（第 402 行：`a != "" && a == b`），且 Evaluate 里也调了
  （第 203 行：同目标的历史条目不作为重复依据）；
- **但 `Observe()`（302-306）与 `Seed()`（330-334）构造 recentItem 时都没有给 GoalID 赋值**
  ⇒ 所有历史条目的 GoalID 都是空串 ⇒ `sameGoal("", goalID)` 永远 false ⇒ **豁免完全失效**。

于是：autonomy 每 3 秒为同一目标生成同一阶段任务 → 第一条进入 recent 窗口 →
后续每条都与它 `fingerprint` 完全相同 → 被「完全重复」硬拒 → 无限循环。

注释里写着「端到端实测修复」（第 193-200 行），说明作者知道这个问题并加了豁免，
但漏了给 recentItem 填 GoalID —— **修了一半**。

## 修复（一行，两处）
```go
// Observe() 与 Seed() 构造 recentItem 时补上：
GoalID: t.GoalID,
```

## 应急（本轮已执行，配置侧）
`PUT /api/eval/config` 把 `repeatGate` 置 false。效果立竿见影：
19:53:47 任务 approved→queued→running，WAL 洪水停止（总行稳定）。
代价：短期内没有重复任务硬门禁（真重复会靠内容与人工发现）。

## 建议
1. **Lead 源码侧**：补上两处 `GoalID: t.GoalID`（一行×2），然后把 repeatGate 恢复 true；
2. **根治「无退避重试」**：autonomy 连续 N 次生成同类被拒后应指数退避，
   而不是 3 秒一次（本轮 187 次拒绝 + R19/R20 两次同族问题）；
3. rejected 任务也写一条 INFO 到 jsonl（现在只进 WAL，现场表现为静默）。
