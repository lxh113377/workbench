# 契约治理规范（全生命周期）

> 版本 1.1.0 ｜ 适用范围：个人 AI 自动化工作台（WorkBench）全部对外/对内契约
> 机器实现：`workbench/internal/gov`（状态机 / 权责表 / 合规分 / 预警）
> 数据落盘：`<数据根>/governance/contracts.json` + `archive.jsonl`
> 面板入口：`/governance`（独立控制台）｜ `/admin` → 治理页签 ｜ CLI：`workbench.exe --governance status`

## 1. 目的与边界

把契约从「谁想起谁管」变成「五阶段状态机 + 节点权责 + 机器校验」：

- **可追溯**：每次阶段迁移写一条留痕（谁 / 何时 / 为什么），归档流水进 `archive.jsonl`
- **可量化**：每份契约有合规分（0-100），机器可复算
- **可预警**：高风险条款 / 到期 / 阶段停留超 SLA / 履约偏差四类预警
- **不可绕过**：阶段只能逐级前进或回退，直改阶段在存储层就被拒绝

**边界**：本规范管「契约治理流程与判据」，不替代法务审查实体，也不做电子签章。

## 2. 生命周期五阶段（唯一状态机）

```
起草 draft → 审核 review → 签署 signed → 履约监控 performing → 归档 archived
```

| 阶段 | 进入条件 | 退出条件 | 机器判据 |
|---|---|---|---|
| 起草 draft | 五要素齐全（标的/金额/期限/交付物/违约责任） | 负责人确认业务口径并指派审核人 | `MissingDuties()` 为空 |
| 审核 review | 审核人 + 合规官已指派 | 法务/业务双审通过，风险条款签字 | 高风险条款 `signed=true` |
| 签署 signed | 审核结论一致 | 签署登记完成（生效日 + 履约节点计划） | `SignedAt` 已写入 |
| 履约监控 performing | 里程碑计划已建立 | 交付物与付款全部核销 | 按期交付率 ≥ 80% |
| 归档 archived | 履约证据链完整 | —（终态） | `ArchivedAt` 已写入 + 归档流水已落 |

状态机规则（代码强制，`gov.CanTransition`）：

1. 只能迁移到**紧邻**阶段；跨阶段一律拒绝（HTTP 400 / 存储层报错）
2. 允许回退到前一阶段（审核打回、履约异常），但**必须填写原因**并留痕
3. 归档为终态；需要新合作时开启新版本契约，不得复活归档件
4. 任何迁移必须填操作人——没有责任人的迁移不是治理，是数据污染

## 3. 节点权责表（RACI，唯一真相源 = `gov.LifecycleDuties()`）

| 阶段 | 角色 | 职责 | SLA（小时） | 必填 |
|---|---|---|---|---|
| 起草 | drafter | 按模板起草，五要素齐全 | 48 | 是 |
| 起草 | owner | 确认标的与业务口径，指派审核人 | 24 | 是 |
| 审核 | reviewer | 法务/业务双审：条款风险、金额上限、体量承载 | 72 | 是 |
| 审核 | compliance | 合规校验：审批留痕、权限匹配、关联方披露 | 48 | 是 |
| 签署 | signer | 签署审批，须与审核结论一致 | 24 | 是 |
| 签署 | owner | 签署登记：归档编号、生效日、履约节点计划 | 24 | 是 |
| 履约监控 | perf-monitor | 按里程碑核对交付物与付款，偏差超阈值即预警 | — | 是 |
| 履约监控 | compliance | 履约合规抽查，每季度不少于一次 | — | 否 |
| 归档 | archivist | 正文 + 审批留痕 + 履约证据链完整入库 | 120 | 是 |
| 归档 | owner | 结项结论与遗留风险移交 | 72 | 是 |

> 权责表是**代码与文档共用**的一张表：改表必须同时改 `gov.LifecycleDuties()` 与本文，
> 并跑 `go test ./internal/gov/`（有测试锁定必需项）。两张表不一致视为治理失效。

## 4. 合规评分模型（0-100，可复算）

| 维度 | 权重 | 计分规则 |
|---|---|---|
| 权责完整 | 30 | 已到达阶段的必需角色齐备比例 |
| 要素齐全 | 30 | 六要素（名称/金额/到期日/交付物/条款/相对方）各 5 分 |
| 审核质量 | 20 | 审核人 + 审核意见 + 合规留痕，各 1/3 |
| 留痕完整 | 20 | 已到达阶段的迁移留痕覆盖率 |
| 扣分项 | — | 高风险未签条款每条 -4；每次争议 -5；质量 <60 -10；交付/付款率 <80% 各 -8/-6 |

判据：**合规分 < 70 即触发预警**（`AlertOptions.ComplianceMin`，默认 70）。

## 5. 风险预警机制（四类，全部带机器可复核证据）

| 预警 Kind | 触发条件 | 严重度 | 处置 |
|---|---|---|---|
| `contract.clause-risk` | 存在风险等级 ≥3 且未签署的条款 | critical | 回审核阶段补齐审签，未签前不得履约 |
| `contract.expiring` | 距到期 ≤30 天（≤7 天升 critical） | warn/critical | 启动续签或结项评估 |
| `contract.expired-unarchived` | 已过期且未归档 | critical | 立即核对履约并走归档 |
| `contract.stage-dwell` | 当前阶段停留超过该阶段最长 SLA | warn | 催办或打回上一阶段留痕 |
| `contract.compliance-low` | 合规分 < 70 | warn | 按缺失项逐条补齐 |
| `contract.perf-deviation` | 交付率/付款率 <80%、质量 <60、有争议 | warn/critical | 要相对方整改，下调体量承载评级 |

每条预警必须同时具备 `Detail`（人读）、`Suggestion`（处置）、`Evidence`（`key=value` 机器可复核）三字段——缺任一视为判据不合格。

## 6. 归档管理

归档不是"存起来"，是**可审计的收敛**：

1. 归档前三查：交付物齐全、付款核销、证据链完整（每项都要有 `Milestone.DoneAt` 或等价留痕）
2. 归档动作自动写 `archive.jsonl`（时间 / 契约 ID / 动作 / 合规分）
3. 归档件只读；任何变更以新契约编号发起，禁止改写历史
4. 逾期未归档（`contract.expired-unarchived`）计入考核项 K2

## 7. 落地命令与验收

```powershell
workbench.exe --governance status      # 只读总览（契约/体量/预警/联动/考核）
workbench.exe --governance checklist   # 只跑考核校验，输出 JSON
workbench.exe --governance json        # 全量 JSON（供自动化）
workbench.exe --governance sample      # 采一次样并重算
```

HTTP（需 `X-WB-Token`，见 `/governance` 页面注入）：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/gov/summary` | 治理总览 |
| GET/POST | `/api/gov/contracts` | 列表 / 新增 |
| GET/DELETE | `/api/gov/contracts/{id}` | 详情（含合规分与缺失项）/ 删除 |
| POST | `/api/gov/contracts/{id}/transition` | 阶段迁移 `{to,actor,note}` |
| GET/POST | `/api/gov/budget` | 体量阈值读取 / 更新（回显生效值） |
| POST | `/api/gov/sample` | 立即采样 |
| POST | `/api/gov/recompute` | 重算预警/调整/联动 |
