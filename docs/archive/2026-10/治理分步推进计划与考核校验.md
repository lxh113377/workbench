## 2. 考核校验标准（六项 K1-K6，机器可复算）

| 编号 | 名称 | 目标 | 判级规则 | 证据字段 |
|---|---|---|---|---|
| **K1** | 契约权责与要素齐全 | 契约数 > 0 且合规均分 ≥70 | 0 份 ⇒ unverified；≥70 ⇒ pass；<70 ⇒ fail | `complianceAvg / low / total` |
| **K2** | 到期/逾期契约治理 | 逾期 = 0 | 逾期 >0 ⇒ fail；否则 pass | `overdue / expiringSoon` |
| **K3** | 体量三域无红区 | 红区指标 = 0 | 无有效采样 ⇒ unverified；有红 ⇒ fail；否则 pass | `domains / redDomains / level` |
| **K4** | 契约×体量数据链路可用 | 采样 ≥3 点 | 0 点 ⇒ unverified；1-2 点 ⇒ fail；≥3 ⇒ pass | `samples / gaps` |
| **K5** | 自适应调整有落点 | escalate 建议均已处置 | 有未处置 escalate ⇒ fail；否则 pass | `escalate / totalAdjust` |
| **K6** | 风险预警闭环 | critical = 0 | critical >0 ⇒ fail；否则 pass | `critical / warn / total` |

**汇总规则**：fail ≥3 ⇒ 红；有 fail ⇒ 黄；全 pass 但有 unverified ⇒ 未验证；否则绿。

**总等级联动**：考核结果反向影响治理总等级——K 项 fail ≥3 时总等级强制为红，
避免出现「总等级绿 + 考核 2 项 FAIL」的自相矛盾读数。

## 3. 三态语义（为什么不是二元 PASS/FAIL）

| 态 | 含义 | 典型场景 | 是否算不合格 |
|---|---|---|---|
| `pass` | 有数据且达标 | 契约 5 份、均分 82 | 否 |
| `fail` | 有数据但不达标 | 契约合规均分 55 | **是** |
| `unverified` | 没数据，无法判定 | 新装环境契约 0 份 | 否（但必须给出补数计划） |

理由（一手教训）：把所有"没数据"都判 FAIL，会让新装环境一启动就红一片，
判据立刻被当成噪声忽略——**判据的价值取决于它红的时候有人在看**。

## 4. 迭代触发条件

| 触发 | 动作 |
|---|---|
| 连续 2 个采样周期同一指标红 | 自动给出 escalate 调整建议（滞回） |
| 连续 3 个采样周期同一指标绿且占用 <50% | 给出 relax 建议（回收余量） |
| 考核 fail ≥3 | 总等级红，冻结新增体量直到收敛 |
| 任一 critical 预警存续 >7 天 | 升级到周度复盘议程（人工介入） |
| 阈值连续调整 3 次仍红 | 说明不是阈值问题，改为排查根因（指标口径 / 资源瓶颈 / 合规缺口） |
