# 三份内嵌 JS 的同名 helper 分叉审计 —— 五轴审查报告（2026-10-25 · round 122-124）

> 范围：`assets_script.go` / `assets_gov.go` / `assets_pool.go` 三份内嵌 JS（各自 IIFE，不共享模块）。
> 可直接贴 PR。所有数字为实测，含测量方法与**我自己的错**。

## 0. 结论先行

审计动机：三份复制粘贴的内嵌脚本是本项目「单 EXE 零依赖」换架构的代价，round 108 已为
`api()` 立过一致性契约。本轮把**所有同名跨 blob 的定义**过了一遍，找到 1 处实质分叉并修掉，
另有 2 类差异**经核实不是缺陷**（登记理由，不硬统一）。

## 1. 正确性

- **P2｜`toast` 自动隐藏延时三副本分叉（已修）**：实测
  `app=2600ms、gov=2600ms、pool=3000ms`。git 归因：两个值**都自「仓库损毁后全量恢复」
  提交 `a5cf134` 就并存**，代码与 docs/CHANGELOG 里无任何注释说明 3000 是有意为之
  （`git grep -i toast` 在 docs/CHANGELOG 中带 4 位毫秒数的记录为 0 处）⇒ **复制漂移，非设计**。
  后果轻：模型池页的通知比别处晚 0.4 秒消失，用户会感知"这三个页面的提示不一样"。
  **统一到 3000 而非 2600**，依据是实测消息长度而非投票：

  | blob | 字面消息数 | 最长字面 | 动态拼接 | 原值 |
  |---|---|---|---|---|
  | app | 40 | **30 字**（"详情面板缺失（渲染契约错误）：#taskDetail 未挂载"） | 18 条 | 2600 |
  | gov | 2 | 5 字 | 0 | 2600 |
  | pool | 14 | 8 字 | 1 条 | 3000 |

  app 的消息最长、动态拼接最多（错误文案可达数十字），却拿着**最短**的停留时间 ——
  这是分叉里唯一有方向性的证据，所以取较长值统一（若压到 2600 会让长错误提示更难读完）。

- **P2｜`esc` 有两种写法但未构成缺陷（不修）**：app/pool 用表查 `c => ESC[c]`，
  gov 用内联对象。**行为等价**（本轮当场跑 `TestAppJSEscCoversAllDangerousChars` 复验，rc=0）：
  三个子测试各自报出本 blob 的 `esc(` 使用数 **appJS 60 / govJS 31 / poolJS 56** ——
  数字互不相同，正好证明测试**真的各读各的 blob**（round 111 那个 `js := appJS` 参数遮蔽
  会让三行都印 60，即只测一份却报三份绿），helper 签名是 `checkEscContract(t, blobName, js string)`
  无遮蔽。round 111 删掉 `|| c` 兜底后，三副本都是「漏一个字符就返回 undefined」的严格形态。
  本轮把它纳入统一判据的收益低于成本 —— 两种写法都短、都有独立行为测试守着，
  强行统一反而要把 gov 也拖进 `ESC` 表，多一个跨 blob 共享常量的维护面。

## 2. 架构（本轮主要产出）

- **P2｜同名跨 blob helper 的清单（实测，缩进容错后才拿到）**：
  app 定义 56 个、gov 21 个、pool 28 个；
  三 blob 同名 = `api, esc, toast`；app∩pool 8 个；app∩gov 4 个；gov∩pool 4 个。
  逐个做 brace-match 提取 + 去空白归一比较，结果：
  `api / armConfirm / disarmArm / fmtTime` **逐字节相同**；
  `toast` 唯一实质分叉（已修）；`esc` 写法不同但行为等价（§1）；
  `fold / TOKEN / disarmArm / fmtTime` 实测**逐字节相同**（同职责复制体，已一并纳入判据）；
  `renderOverview / render / load` 才是同名异义（三处渲染不同 DOM，签名也不同：app 的
  renderOverview 是无参 async 函数、pool 的接收数据）。

- **本条我改过一次，原因必须写明**：首次比较用「花括号配对」提取函数体，而这些 blob 里既有
  块体函数也有箭头表达式体（`const fold = (title, body) => '<details …>'` 无花括号），配对逻辑
  于是从 fold 一路吞进后面的函数，给出 fold 与 renderOverview **相同长度**的假数据，我据此把
  逐字节相同的 fold 误分类成「同名异义」。改用**按缩进取块**重测后 fold 两侧 127/127 相同。
  教训：提取器出错的症状是**两侧长度相等**而不是不等 —— 只盯「有没有分叉」，看不见
  「我比较的对象是不是同一件事」。

- **为什么只把 toast 纳入判据、不把「所有同名 helper」纳入**：`load` 在 gov 是治理页刷新、
  在 pool 是模型池刷新，`render` 在三处渲染不同 DOM —— 同名异义是本项目的既有约定，
  判据要求它们相同是错的。**判据必须只覆盖「同职责的复制体」**，这条边界写进了测试注释。

- **轮询周期差异不统一（如实登记）**：`gov.load=30000ms` vs `pool.load=15000ms`。
  两者数据体量与变更频率不同（治理契约 vs 模型健康），且 round 111 已核证
  `handleGovSummary` / `handlePoolStatus` 不做网络、不碰 `e.mu`，不是同源风险。
  统一成一个周期会让某一侧无谓变慢或变快，属**产品取舍**，不是工程缺陷。

## 3. 可读性

- 新增 `web/toast_duration_contract_test.go`，注释里写清：分叉实测值、git 归因、
  为什么取 3000（附消息长度表）、判据边界（只覆盖同职责复制体）、以及「本测试不判
  2600 还是 3000 对，只判不许分叉」——与 round 108 的 api 契约同一措辞传统。

## 4. 安全

- **P2｜审计了「某 blob 引用了自己没定义的跨 blob helper」**（这类 bug Go 侧测不出，
  浏览器才抛 `ReferenceError`）。**结论：无真缺陷**，5 处命中全是我的扫描器造成的假阳性：
  `s`/`body` 是箭头函数形参（我的 `defined()` 不收集形参）、`raw` 是对象字面量的键
  （`{ raw: text }`，不是引用）、`p`/`fold` 逐行重扫为 0 次（全文件正则与逐行正则
  因跨行字符串剥离给出不同结果）。⇒ 见「门禁建议 #2」：这个判据形态**不可用**。

## 5. 性能

- **本轴未发现问题**，检查了什么：toast 只是 CSS class 增删 + 一个 `setTimeout`，
  无分配热点；三副本内嵌脚本的体积影响为零（只改 3 个字符）；`ping=4000` /
  `refreshTop=5000` 两个同 blob 定时器已有 `poll_guard_contract_test.go` 守着
  重入与超时（round 111）。

## 5.5 判据泛化与一处门禁缺陷（round 124 追加）

- **判据从「只管 toast」扩到七组同职责复制体**：文件 `git mv` 改名为
  `helper_identity_contract_test.go`（保留历史），cases 覆盖 **api / toast / TOKEN /
  armConfirm / disarmArm / fmtTime / fold**，并加两道防自转结构：① 抽取失败即报错并点名
  「判据失去受理面」；② 归一长度低于登记值一半即报「提取法可能退化，判据在比空气」。
  三项变异全部判红闭环：真实代码分叉（poolJS 的 `zh-CN` 改 `en-US`）⇒ 点名 fmtTime；
  提取法退化（只取首字符）⇒ 报归一长度 0 远低于登记值；把 fold 改名 ⇒ 报受理面失效。
  哨兵值取 Go 侧实测（fmtTime 79，不是我 JS 侧记的 77；差 2 来自注释剥离方式不同，
  两侧独立实现给出同结论，属互证而非矛盾）。
- **注释差异不算分叉（判据太严会假红）**：首版把 armConfirm 判成分叉，实际代码逐字相同，
  差在 appJS 有一条行尾注释、poolJS 多两行整行注释。正解是复用仓内已被
  `TestStripLineCommentsIsSound` 四项自检验过的 `stripLineComments`，而不是再写一个更难保证正确的
  剥离器 —— 与 round 64 家族同源（判据不准），只是这次方向是**误报**。
- **发现并修复 check_gofmt 的顺序死结（真实缺陷，不是并行会话的锅）**：清单来自 `git ls-files`
  （含已 stage 未提交的新文件），而 HEAD blob 取不到 ⇒ 一律记成「HEAD 漂移」判红。这与本仓验证
  流程（先 `git add` 让 check_report_figures 的未跟踪计数反映提交后状态）直接冲突，形成
  「必须先提交才能跑绿、提交前又必须跑绿」。修法：先用 `git ls-tree -r --name-only HEAD` 一次性
  列出 HEAD 路径，按存在性选 `HEAD:$rel` 或 index 的 `:$rel`。**第一版写成「HEAD 失败就重试
  index」是错的** —— 脚本 `$ErrorActionPreference='Stop'`，native 往 stderr 写 fatal 会被当异常抛出，
  失败路径走不完（本仓在册同族坑）。双向验证：当前态（含已 stage 新文件）rc=0；stage 一个
  真不合规的新文件 ⇒ rc=1 且点名；清理后回 0 无残留。

## 合并结论

**可合并。**

1. 代码改动面极小（app/gov 各把 `2600` 改成 `3000`，共 2 处 6 字符），`assets_pool.go` 一字未动即已一致；
2. **双向变异闭环**：变异 A（把 poolJS 的 `toast` 改名）⇒ rc=1 并点名
   「判据失去受理面（空转），请同步本测试」—— 证明判据不会因抽不到函数而静默绿；
   变异 B（pool 单边退回 2600）⇒ rc=1，打印首个差异位置（第 206 个非空白字符）与两侧片段；
   还原 ⇒ rc=0，且 worktree 内完成、主仓 `assets_pool.go` 复验 clean；
3. 统一方向有实测依据（消息长度表），不是取多数或随手挑一个；
4. web 包全量 rc=0。
