> 范围：`tests/check_*.ps1`（受跟踪 41 个）里**依赖运行环境**的那批 —— 依赖 git 历史（**初稿口径过宽，精确分类见 §1.1**）、
> 或读外部数据件的那批。可直接贴 PR。所有数字为实测，含**被我自己推翻的两个假设**。

> 一句话结论：**这批门禁经实测没有发现「环境失真导致假绿」的实例**；两个假设都被数据推翻，

## 0. 结论先行

| # | 假设 | 实测结论 | 证据 |
|---|---|---|---|
| H1 | CI 用 `fetch-depth: 1` 浅克隆，依赖 git 历史的门禁可能**取不到历史而静默判绿** | **推翻**（无差异） | 5 个门禁在完整克隆与 `--depth 1` 克隆下 rc 与实质输出一致；它们用的是 index/HEAD 层 API，不依赖历史深度 |

## 1. 正确性

- **H1 的实测方法（可复跑，完全离线）**：
  ```powershell
  git clone --depth 1 --no-local file:///<仓库绝对路径> <TEMP>\shallow   # 不用网络也能造浅克隆
  git -C <TEMP>\shallow rev-list --count HEAD                            # 实测 = 1
  # 然后对同一批门禁分别在完整树与浅克隆里跑，比对 rc 与实质输出
  ```
- **实测对比表**（完整克隆 vs 浅克隆，rc 全一致）：

  | 门禁 | 完整 | 浅克隆 | 浅克隆下的实质输出（证明在干活，不是空转） |
  |---|---|---|---|
  | check_doc_refs.ps1 | 0 | 0 | 74 份活文档、103 处 `tests/*.ps1` 引用均可解析或已披露 |
  | check_multi_bom.ps1 | 0 | 0 | 查 1739 个受跟踪文本文件（单BOM=84 无BOM=1655 多BOM=0 缺HEAD=0） |
  | check_gate_coverage.ps1 | 0 | 0 | 41 个门禁脚本全部至少挂一个受理面（检查了 4/4 个受理面） |
  | check_gofmt.ps1 | 0 | 0 | 检查 354 个受跟踪 .go，23 个登记豁免 |
  | check_stdlib_only.ps1 | 0 | 0 | go.mod 无 require、无 go.sum、无 vendor、无外部 import |
  | check_ps1_eol.ps1 | 0 | 0 | 「暂存区无 .ps1 文件（无需 EOL 检查）」 |
  | check_artifact_soak_fresh.ps1 | 0 | **2** | 浅克隆里无 dist 产物 ⇒ **UNVERIFIED**（不是判绿） |

- **为什么 H1 站不住**：这批门禁读的是 `git ls-files`（**索引**层）、`git cat-file`、
  `HEAD:<path>` 回退 —— 浅克隆的索引与 HEAD 树都是完整的，缺的只是**祖先提交**。
  `check_artifact_soak_fresh` 更进一层：拿不到产物时显式走 rc=2 并写明「没测成 != 合格」。
- **H2 站不住**：`check_multi_bom` 头注 L21 明说「单 BOM 与无 BOM 都合规（…`.ps1` 必须带
  BOM，两类都不该被强迫改）」，它把「.ps1 有没有 BOM」交给 `check_ps1_encoding`；后者实测
  受跟踪、在 ci.yml、判据为「受跟踪的 .ps1/.psm1 若含非 ASCII 字节必须带 UTF-8 BOM」。
  两者**职责不重叠**，不是漏洞。

## 1.1 侦察口径的自我更正（round 151 实测 —— 本报告第二次自我推翻）

- 本报告初稿写「41 个受跟踪门禁里 **9 个**用 git 历史」，那是**整文件正则（含注释）**的结果，口径太宽。
  改为「只看非注释代码行」重测后，真实分类是：

  | 类别 | 数量 | 实测证据 |
  |---|---|---|
  | 真依赖**祖先提交**（浅克隆下可能取空） | **1** | `check_artifact_soak_fresh.ps1` L84：`git log -1 --format=%ct -- <4 个路径>` |
  | 只用 **HEAD 作用域** API（浅克隆安全） | 5-6 | `cat-file` / `HEAD:<path>` / `git archive HEAD` / `checkout-index -a -f` |
  | 零 git 调用：`git log --all` 只在**头注释**里 | 1 | `check_doc_refs.ps1` L4（描述的是过去那次人工自查，不是运行期依赖） |
  | `git log` 只在 **Write-Host 提示串**里 | 1 | `check_snapshot_build.ps1` L91 的 `Write-Host "  自查: git log --all -- <缺失文件> …"` |

- **这条更正同时否掉了 G1/G2 的做法**：静态检测「是否依赖 git 历史」无法把**真调用**与
  **打印给用户看的自查命令**分开 —— `check_snapshot_build.ps1` L91 就是反例，任何朴素
  扫描器都会把它误判成依赖。按本仓在册立场（`check_ps1_encoding` 作者拒绝「头注语义必须与
  实现一致」这类判断，理由同样是「会制造噪声」），**会误报的模糊检查不该建**。
- **风险链已被现有设计闭合**（实测）：唯一真依赖祖先提交的那个门禁，取空时走 `Unverified`（其 L97
  原文「相关源码在 HEAD 没有提交记录（异常）」），而 `ci.yml` L228 **显式容忍 rc=2**
  （`if ($rc -eq 2) { Write-Warning …; exit 0 }`）。即浅克隆下最坏结果是「没测成」，
  **既不是假绿也不是假红**。
- 于是落地方式改为**设计期约束**：把「依赖 git 历史的判据必须处理浅克隆取空、并写明由谁容忍 rc=2」
  编码进 `quality-gate-spec` 的新 ⑦（见 §6「后续动作」）。这比运行期扫描判据更早、更省、也不会误报。

## 2. 可读性

- 这批门禁的头注质量普遍高：都写了「为什么需要（真实事故+代价）」「判据（窄面、可证伪）」
  「退出码」三件套，且把**手工取证命令**留在注释里，使我能直接复跑而不是猜。
- 一处**自陈盲区**（`check_ps1_encoding.ps1` L14-20）：它的头注曾比实现旧两天
  （声明「受跟踪与未跟踪都查」，实现只查受跟踪）而无人发现，原因写得很准 ——
  `check_comment_staleness` 只抓「只剩/共 N」这类**数字**断言，抓不到**语义声明漂移**。
  作者选择留档而不扩判据（「扩了就是模糊语义检查，会制造噪声」）。我认同这个取舍：
  它避免了 F 型误报（见 §5.6）。

## 3. 架构

- 「依赖环境的部分**显式声明并降级**」是本仓的既定架构，但**降级方式按门禁而异** ——
  我原先在本节写下「抽查 4 个读外部数据件的门禁，输入缺失时都走 rc=2」，**这句被实测推翻**：
  我在**干净克隆**里跑这 4 个（干净克隆天然没有未跟踪文件、没有 `.workbuddy/memory/gate-readings.jsonl`），
  实测 rc 是 **0 / 0 / 0 / 1**，一个都不是 2。逐条更正：

  | 门禁 | 干净克隆里的 rc | 为什么这是对的（读了它的实现与头注） |
  |---|---|---|
  | check_untracked_go.ps1 | 0 | 干净树里未跟踪件本就为 0 ⇒ 差额 0 ⇒ PASS 正确；读数文件只是「有没有历史基线」，缺了不改变本次判定 |
  | check_skip_disclosure.ps1 | 0 | 核心判定在受跟踪 `_test.go` 列表上（`git ls-files`），读数文件用于趋势，缺了不影响本次 rc |
  | check_readings_trend.ps1 | 0（并打印存在性告警） | 它在克隆里仍找到了可读的读数数据；「已声明落盘却零读数」只作告警，不升 rc |
  | check_report_figures.ps1 | **1** | **设计如此**：它判**工作区**，干净树未跟踪数必为 0，与报告写的本地实测值 29 不符 ⇒ 判红。其头注 L27-30 明写「本件属于本地判据，**不挂 CI repo-gates**（挂了会在干净检出上永远红）」，并实测 ci.yml 里确无它、有它的是 check_all |

  **这条更正本身有额外价值**：干净克隆不只是一个「浅克隆模拟器」，它还是**判据分级（本地判据 vs CI 判据）的验证器** ——
  一个在干净树里判红的门禁**必须**不挂 CI；`check_report_figures` 把自己的分类与理由都写在头注里，实测与其声明一致。
  见 §6 的 G4。
- 两个债务基线门禁（`check_dead_css_tokens` + `tests/css-token-debt.txt`、
  `check_gofmt` + `tests/gofmt-debt.txt`）是**失效安全**方向：删掉债务文件判据只会更严
  （所有条目都算新增 ⇒ rc=1），不会变松。
- 真正需要新增的**不是判据**，而是**环境维度**（§6）。

## 4. 安全

- 本次审计未涉及权限面；仅记录一处与「安全边界」相邻的事实：`check_ps1_eol` /
  `check_staged_bom` 是**暂存区**口径（本地 pre-commit 用），在 CI 里必然打印
  「暂存区无 .ps1 文件」并 rc=0。这**不是漏洞**（CI 的等价面由 `check_ps1_encoding` +
  `check_multi_bom` 在受跟踪列表上覆盖），但读读数时要意识到「这两条在 CI 里是空转的绿」。

## 5. 性能

- 浅克隆模拟的代价：一次本地 `--depth 1` 克隆 + 7 次门禁运行，在本机约 1 分钟量级；
  若不引入 §6 的常驻判据，这条方法只作为**人工复核**手段（低频、按需）。
- 若采纳 §6，需注意 `check_snapshot_build` 已有「临时目录克隆」范式可复用，避免再写一套。

## 5.6 反误报：我刻意没有做的事

- **没有**加「头注语义必须与实现一致」的判据：那是模糊语义检查，误报率不可控，
  正是 `check_ps1_encoding` 作者已经权衡并拒绝的方向。
- **没有**因为「`check_ps1_eol` 在 CI 空转」就删它：它的受理面是本地 pre-commit，
  删了会让「提交前 EOL 检查」整体消失（三态设计里它的位置是对的）。

## 6. 门禁建议（供下游 agent 落地）

| # | 建议 | 依据 | 成本 | 建议 |
|---|---|---|---|---|
| G1 | 新增「浅克隆一致性」判据：在 TEMP 里 `git clone --depth 1 --no-local file://<root>`，对**声明依赖 git 的**门禁跑一遍，断言 rc 与完整树一致（至少断言不出现「完整树判红 / 浅克隆判绿」的方向差） | 本报告 §1 的实测表是它的基线；现有 7 个门禁已知基线全绿 | 中（复用 `check_snapshot_build` 的克隆范式） | **已降级（不采纳，见 §1.1）** —— 其诉求已由设计期约束（gate-spec ⑦）承接；原文曾主张：先固化「哪些门禁声明依赖 git」的名单，否则会误抓不依赖历史的门禁 |
| G2 | 把「哪些门禁依赖 git 历史」写进一个显式清单（如 `tests/git-dependent-gates.txt`），由 G1 消费 | **已降级，见 §1.1**（初稿口径含注释故过宽）——整文件正则曾命中 `git log/--all/cat-file/show HEAD` | 低 | **不采纳**（静态检测无法区分真调用与提示串） |
| G3 | 给 `check_ps1_eol` / `check_staged_bom` 的输出加一句「本判据的受理面是本地 pre-commit，CI 下为空转」 | 读读数的人会以为它们在 CI 里也在守 | 极低 | 建议采纳 |
| G4 | 用「干净克隆」验证**判据分级**：每个挂在 CI repo-gates 的门禁都必须在**干净树**（`git clone` 后无未跟踪件、无本地读数文件）里可判绿；反之在干净树里判红的门禁必须在头注声明「本地判据、不挂 CI」并确有其事 | 本报告实测：`check_report_figures` 干净树 rc=1 且头注已声明不挂 CI，实测一致；而没有任何机制阻止后续把环境依赖型门禁误挂 CI（虽然那会**响亮地**红，不是静默） | 低-中（可并入 G1 的同一套克隆夹具） | 建议采纳（优先级低于 G1） |
