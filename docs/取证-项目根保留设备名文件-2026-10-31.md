## 实测危害矩阵（2026-10-31 round 168，在同一临时目录造同名文件后逐个测）

| 工具层 | 结果 |
| --- | --- |
| [IO.File]::WriteAllText 创建 | ERR「FileStream was asked to open a device that was not a file」（.NET 连创建都拒绝）|
| [IO.File]::Exists | False（存在性检查看不见它）|
| Get-ChildItem 枚举 | 能列出（看得见）|
| Get-Item / Get-Content 按路径 | ERR 找不到路径 |
| [IO.File]::ReadAllText | ERR device not a file |
| \?\ 扩展路径前缀读（社区推荐解法）| 同样 ERR |
| Remove-Item -LiteralPath | ERR ItemNotFoundException ⇒ 删除失败 |
| Copy-Item -Recurse | ERR IOException ⇒ 递归备份失败 |
| Compress-Archive | ERR IOException ⇒ 打包失败 |
| node fs（libuv，内部走 \?\）| stat / read / copy / **unlink 全部成功** |
| git status / ls-files | 正常（未跟踪 ⇒ CI 克隆不受影响）|

⇒ 危险面精确到「.NET / PowerShell 系的清理与备份工具会在它上面失败」；本仓 tests/ 下 48 个门禁
  与清理脚本都是 PowerShell 系 ⇒ 一次 nul 就能让整轮备份/清理失败，且 [IO.File]::Exists 返回
  False 会让"先判断再删"的脚本**静默跳过**它（比报错更糟）。
⇒ 删除办法（实测可用）：node 的 fs.unlinkSync。
