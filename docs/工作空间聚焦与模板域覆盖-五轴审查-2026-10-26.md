## 3. 架构

目标要实现的是「**工作空间选择 → 注入 → 模板域 → 选题池**」四段对齐的一条可扩展链路。现状（实测）：

```
--workspace select <dir> ──► config.Workspace{Mode,Root} ──► Manager.Root() / IsExternal()
   (cmd/workbench/main.go:494-514)        │                        │
                                          │                        └─► engine.workspaceContextText() ──► Runner.SetWorkspaceContext
                                          │                              (engine.go:1896-1901)      (executor.go:153-161)
                            ┌─────────────┴──────────────┐
                 Templates(29 条 / 7 域)          chain.topicsByDomain(6 域，缺 quality)
                            │                              │
                            └──► RootTask / Successor：prompt = Render(tpl, {Topic=pickTopic(domain), Context})
```

缺口是**三个断点**，都可独立小步修：

1. **选择断点**：`--workspace reset` 残留 Root（§1.1）+ `normalizeWorkspace`（`internal/config/config.go:856-865`）
   在 external 但 root 为空/非绝对时**静默降级**为 project —— 本仓最忌讳的「隐身失败」：选择丢了不留痕、不告警。
2. **选题断点**：`topicsByDomain` 的键集合与模板域集合**没有任何判据对齐** —— 域加一个、池忘加，就静默回落 content（§1.2）。
3. **模板断点**：新增域/模板没有「覆盖率」判据，也没有「prompt 必须绑定当前工作目录」的约定（§1.3）。

**扩展口径（这就是「可扩展」的落地定义）**：新增一个域 = ① `defaults.go` 加模板（含 `DiversityGroup=domain` 与 `Chain` 后继边）；
② `topicsByDomain` 加同键**非空**池；③ `templates_test.go` 的条数 / `want` / `wantCount`；④ `defaults.go:25` 头注释；
⑤ 跑 §8 的复验命令。五步缺一即半成品，第 ② 步已有可机判判据（§6 门禁建议 1）。
