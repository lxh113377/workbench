### 1.15 T15-② 实测闭环（round 15）：探测不再抹掉执行侧失败，首路由不再永远落在零产出模型上

**缺陷（有账本数据）**：`ApplyProbe` 的 StateHealthy 分支原先无条件 `ConsecFail = 0; Success++; CooldownTo = 0; LastErr = ""` ——
探测只证明「端点可达」，却被当成「模型会产出」。实测健康账本：`deepseek-ai/deepseek-v4.1-flash`
`succ=17 fail=3 **consec=0** cooldownTo=0 state=healthy`；同一时刻 `model-status.jsonl` 里是
`probe: from degraded to healthy（探测状态变化）` + `本轮探测 36 个：可用 36 / 下线 0` ⇒ **每轮探测把执行侧刚记下的失败擦掉**，
于是每个新任务的首个路由永远落在实测跑不出东西的模型上（round 8/9/11/13/14 五次尝试全是它）。

**修法**：新增 `isExecutionFailureKind(kind)` —— 结构性故障（unreachable / missing_credential / bad_endpoint …）可由探测恢复；
执行侧失败（stalled / bad_exit / timeout / upstream_failed）只能由**执行成功**清除。`ApplyProbe` 的 healthy 分支据此分流，
可达性信息（ProbeOK / LatencyMs / State）照旧更新（冷却期内仍被调度器跳过：State=Healthy 但 `CooldownTo > now`）。

