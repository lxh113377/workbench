## 〇、迁移原则（四条，缺一不可）

1. **不"整体替换"，只"受控吸收"**：本仓技能普遍带本仓特化（中文路由、门禁联动、references 分卷），**禁止整文件覆盖**；一律按"上游独有标题/段落"逐节吸收，保留本地特化。
2. **候选须先"存在性实测"再谈替换**：候选入口件必须拿到 `raw.githubusercontent.com` HTTP 200 与真实字节（本轮已对 59 个候选做过，见 `data/candidate-path-verify.json`），**仅凭仓库名/目录链接判断的候选不得进入迁移**。
3. **先冻结基线，再动手**：任何替换前，必须先把"替换前读数"落盘冻结（字节比、上游独有标题数、hitrate 基线）。没有冻结基线的"提升 X%"不成立（见 §五）。
4. **破坏性操作按"备份 + Git 可回滚"双硬前提自动放行，缺一回落待批**（沿用 `A-skill-manager` 铁律 2；备份落 `D:/global_memory/_trash/`，禁止 `_bak` 落点）。

**不可兑现（明确拒绝承诺）**：
