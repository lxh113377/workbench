# 05 · 技能季度巡检与维护规范

> 编制：2026-10-19（Asia/Shanghai）｜配套脚本：`scripts/quarterly_skill_sweep.py`、`scripts/skill_inventory.py`
> 本规范与焚诀既有机制**并轨不并存**：`焚诀/eval/upstream_drift_check.py` 管 4 条加密登记，本规范管本仓 17 条已实测登记。

## 一、机制目标

把"上游发新版 / 出现更优替代 / 本地悄悄走偏"三件事，从**靠人记得**变成**每季度机器扫一遍**，并把结论固化成三态（GREEN / RED / UNVERIFIED），**取不到数一律 UNVERIFIED，禁止读成通过**。

## 二、登记表（唯一真相源）

`data/skill-watchlist.json`（schema `skill-watchlist-v1`，本轮 **35 条登记**：batch-B 17 + batch-A 18）。每条字段：

| 字段 | 含义 | 谁维护 |
|---|---|---|
| `local_skill` / `local_skill_md` | 本地技能与主文件路径 | 脚本生成 |
| `upstream_repo` / `upstream_path` | 该技能评分最高的已实测候选（代表上游）| 脚本生成，人工可覆盖 |
| `recorded_version` | **本次对表基线**（`github/<repo>/releases.atom` 实测最新 tag）| 脚本生成 |
| `last_checked` | 上次对表日期；超 `fuse_days` 即判过期 → 该条强制 UNVERIFIED | 脚本生成 |
| `candidates` | 全部候选（季度复验活性与优劣）| 调研产出 |
| `discovery_query` | 未来发现"更优替代"的检索式 | 人工/脚本 |

**禁止手改 `recorded_version`**：它必须是脚本从上游取回的实测值，手填等于自造第二真相源。

## 三、扫描器四条腿（每条独立出态，总判定取最差）

| 腿 | 判据 | 取数通道（无需 API 配额优先）| 三态 |
|---|---|---|---|
| 腿1 版本对表 | 登记 `recorded_version` vs 上游最新 release tag | `releases.atom`（无配额）→ `api/releases/latest` → `commits/<branch>.atom` | 相等 GREEN；不等 RED；取不到 UNVERIFIED |
| 腿2 镜像漂移 | 本地 SKILL.md vs 上游同名件：字节比 + difflib 相似度 + 上游独有标题集合 | `raw.githubusercontent.com/HEAD` | 字节比 <0.6 或上游独有标题 >3 判 RED |
| 腿3 候选活性 | 逐候选查 `stars` / `pushedAt` / `archived` | `ungh.cc`（无配额，失败重试 3 次）→ `api.github.com` | 归档或超活跃窗（默认 400 天）判 RED；读数失败 UNVERIFIED |
| 腿4 替代发现（**可选**）| 按 `discovery_query` 搜出"未登记且更活跃"的仓库 | `api.github.com/search`（**有配额**）| 需显式 `--discover N` 启用；未启用记 SKIP（不计入总判定）|

> **腿4 是可选增强**：`api.github.com` 匿名配额 60/小时且共享出口 IP，实测 2026-10-19 22:36 耗尽。**默认关闭**，季度正式跑时在有配额窗口执行。

## 五、裁决规则（扫描出 RED 之后做什么）

| 红在哪条腿 | 裁决选项 | 默认建议 |
|---|---|---|
| 腿1 版本落后 | 吸收 / 保持分叉 / 弃用 / 替换 | **先读上游 changelog 再决定**；本地特化多则保持分叉并在文件内留裁决记录 |
| 腿2 漂移 | 吸收缺失节 / 认领分叉 / 替换 | 相似度 <0.9 优先吸收；上游独有标题即"待补节清单" |
| 腿3 候选失活 | 换候选 / 降级为"无人维护参照" | 失活候选**不得再作为迁移目标** |
| 腿4 发现更优 | 评估 → 替换候选登记 | 新候选必须先过 §六 的准入实测 |

**每次裁决必须在 `data/skill-watchlist.json` 的该条 `notes` 里留一行**：`<日期> 裁决=<吸收|分叉|弃用|替换> 依据=<证据>`。

## 六、新候选准入实测（防止"看着像就换"）

候选进入迁移前必须全部通过：

1. **存在性**：`raw.githubusercontent.com/<repo>/HEAD/<entry_path>` 实测 HTTP 200（本轮 59/59 通过，方法见 `scripts/verify_candidate_paths.py`）。
2. **体量**：记录真实字节数与 SHA256 前缀。
3. **许可**：SPDX 明确；`CC-BY-SA` / 无声明 / `NOASSERTION` 的必须人工确认署名义务。
4. **格式兼容**：同为 `SKILL.md` 目录式；含脚本的候选须查其依赖可安装性。
5. **活性**：`ungh.cc` 或 api 读数，`pushedAt` 距今 ≤ 活跃窗。

## 九、失败与降级

- **网络全断**：`--offline` 跑，全部条目判 UNVERIFIED，报告里明写"离线，未对表"。**禁止**在离线模式下输出 GREEN。
- **`api.github.com` 403**：腿1/腿3 已走无配额通道，通常不受影响；腿4 记 UNVERIFIED 并提示需配额窗口。
- **上游路径改名（raw 404）**：记 UNVERIFIED 并在 `notes` 提示"上游路径可能改名，需重新定位入口件"——不得静默跳过。

## 十、版本基线诚实性（本轮实测发现并已处理）

登记表的 `recorded_version` 必须来自上游真实 tag，**但部分仓库的 release 标题不含语义版本号**（实测：`addyosmani/agent-skills` 的 release 标题就是 "Agent Skills 0.6.13" 这种带项目名的形态，甚至出现两行不同形态的标题）。

- 处理：脚本取 `releases.atom` 的第一个 `<title>` 原文作为基线，**不做正则清洗**（清洗会把"取不到"变成"猜一个"）；
- 后果：对这类仓库，腿1 只在"标题字符串完全相同"时判 GREEN，否则 RED —— 属**保守偏严**，方向正确（宁可报红去人工看，不可静默放行）；
- 无 release 的仓库（`scope-creep-detector` / `commit-archaeologist` / `security-audit` / `grill-me` / 浏览器与办公面多数候选）→ 腿1 记 UNVERIFIED，并在报告里逐条列出"无 release 基线"，不当作 GREEN。

## 十二、自动选品的血缘盲区（2026-10-20 轮5 实测教训）

- `build_watchlist.py` 按「评分最高的已实测候选」自动选代表上游，**按分数不按血缘**：dogfood 被选成相邻件 browser-use/qa（9154B），真同源 vercel-labs（10845B）落选——相邻件可以更大更高分，但它不是上游，漂移腿量的是「与错对象的差距」。
- 修正：登记表允许**手工钉回** `upstream_repo/upstream_path`，并在 `upstream_role` 字段注明修正原因与日期；季度巡检跑前抽查 2-3 条「本地自述 Provenance 有同源声明」的条目是否仍指对对象。
- 判据方向：**漂移腿颜色 ≠ 完成度**。「保持分叉」裁决项（testing / ci-pipeline-debugging）会长期显 RED，这是正确结果——巡检报告的 RED 桶要再分「待吸收」与「已裁决保持分叉」两类，后者不再进工作队列（watchlist.notes 里 `裁决=` 前缀即分类依据）。
## 十三、漂移腿合并口径（2026-10-20 轮9 升级，判据先于动手）

- **变更**：`quarterly_skill_sweep.load_local_merged()` 把漂移腿的本地侧文本从「仅 SKILL.md」升级为「SKILL.md + `references/` 全部 .md 合并」；行内输出新增 `local_main_bytes` 供体量口径单列。
- **为什么**：B3b 把吸收块从主文件迁进 references 分卷后，只看主文件会把「内容仍在、只是换了文件」误判成漂移回归——**先修判据，再动文件**（本轮实测：5 件迁卷前后合并口径 missing_norm 全部保持 0）。
- **连带纪律**：①分卷必须走 `（吸收上游` 类可定位标记，脚本找不到标记即跳过不猜锚点；②迁出块逐字节保留（含卷内 Version history (cont.)）；③主文件留一行指针引用（可被 dead_refs 解析且文件实存）；④改过 SKILL.md 一律 bump patch 版；⑤提交=显式路径 add + cached 名单纯度断言 + numstat 行数核验（本轮并行会话同时改 6 件，纯度断言挡下了一次全仓 add 的污染）。
## 十四、委托壳判定与登记表防覆盖（2026-10-20 轮13 两条一手教训）

**A. 委托壳（薄壳化）不是漂移**。并行会话把 `agent-browser` 做成 v3.0.0 薄壳（38626→4862 B，命令权威改 `agent-browser skills get core --full` 随版获取），`electron` v1.1.0 同类（双路 + `.upstream` sidecar）。壳文本与厚上游比标题＝必然假红（实测壳-上游原始对比 RED/144、RED/174）。
- 判据：本地文本命中 ≥2 个锚点标记（`skills get` / 委托上游 / 薄壳 / `.upstream` / 上游锚点）**且**含 `skills get` 或 `.upstream` → 漂移腿转记「委托壳：漂移由版本腿跟踪」，**原始对比值仍写进 note 留痕可审**（不隐藏）。
- 版本腿继续可比：上游 release tag 与 `recorded_version` 不等仍报红 → 壳内悄悄塞过期内容的风险由这条兜住。
- 不享受豁免的情形：壳无显式锚点（写残的薄壳、或偷偷截断），照判 RED。

**B. 派生件重建会吃掉人工修正**。轮12 为测 import 安全性 exec 了 `build_watchlist.py`，它末尾无条件写盘 → 全量重建覆盖 4 条人工血缘钉（dogfood/electron/agent-browser/security-audit）与 8 条裁决注记，本轮巡检当场表现为 security-audit 假 RED（对 trailofbits 相似度 0.395）、dogfood/electron 上游丢失。修复＝`repair_watchlist_r13.py`（重钉 4 + 补注记 8），防线两条：
1. **写盘需显式 `--write`**（默认 DRY-RUN，防 import/exec 意外触发）；
2. **写前保留**：从现存 watchlist 读 `upstream_role` 含「重钉/修正/钉回/same_origin/discovered_strong_candidate」的条目，其血缘六字段（repo/path/role/version/notes/last_checked）覆盖新值——实测 preserved 41 of 41。

> 两条同族：都属「**判据/派生件没跟上人工治理动作**」。通则：能写权威文件的脚本必须默认 dry-run + 保留人工面；内容搬家类架构（薄壳/分卷/委托）必须先给判据加对应口径，再动文件。
