| DSH 子进程调用（工作台侧） | ❌ 待接线 | `executor.taskHome()` 仍把 aggregate 硬编码成 `{"enabled":false,"providers":{}}`，见下节根因 |

根因链（逐文件核对，字段名对照 OFM 插件源码，未猜标识符）：

1. `executor.go: taskHome()` 每任务写
   `our-free-model/settings.json`，其中 aggregate 被**硬编码**
   `{"enabled": false, "providers": {}}`；
2. `overlay.yml` 由 `modelOverlay()` 生成，只写
   `provider: our-free-model` + `model: <id>`；
3. OFM 插件 `core/runtime.js: mergeCatalogs()` 用
   `buildAggregateCatalog(settings.aggregate)` 生成 aggregate 行并合并进 catalog；
   第 1 步给了空开关 ⇒ **aggregate 行永远不存在**；
4. `adapter.js: resolveModel()` 按 `entry.id` 查 catalog，查不到就回退成
   「免费车道条目」，最终走 `postStreamed`（OFM 匿名池），
   而不是 `postAggregateStreamed`（用户自己的端点）。

**结论**：用户自填端点会被静默改道到免费车道，绝不会打到用户填的 BaseURL。
所以这类模型的正确标记是 `routable:false`（本轮已在
`Scheduler.Pick/PickChain` 补齐这道过滤，见 commit 7e44267）。

## 2. 接通方案（最小改动，零源码依赖新增）

### 2.1 池 → aggregate 配置的投影

在 `taskHome()` 写 settings 前，收集池内「自定义/聚合车道且带 BaseURL」的 Spec：

```go
// 需要把池的 specs 传进 taskHome（现签名只有 taskID）。
// 建议 Runner 上加一个 provider 回调，避免 executor 反向依赖 modelpool。
type AggregateProviderSpec struct {
    ProviderID string // OFM registry 里的 provider id（见 2.2 校验）
    ModelIDs   []string
    BaseURL    string
    APIKey     string
    Format     string // openai-chat / openai-responses / anthropic-messages
}
```

settings 的 aggregate 段按 OFM 契约写（`src/aggregate.js` 的
`buildAggregateCatalog` JSDoc 逐字段核对）：

```json
"aggregate": {
  "enabled": true,
  "providers": {
    "<providerId>": {
      "enabled": true,
      "apiKey": "<key>",
      "baseUrl": "http://127.0.0.1:18432/v1",
      "models": ["openrouter/free"],
      "addedAt": 1700000000000
    }
  }
}
```

```yaml
# overlay 的 model 用 provider/model 复合 id
- id: agent-default-model
  config:
    provider: our-free-model
    model: open_router/openrouter/free
```

### 2.2 三条硬校验（不满足就别接通，否则会静默失败）

OFM 侧 `resolveProvider` / `authUsable` / `effectiveChatUrl` 的实际约束：

1. **providerId 必须存在于 OFM registry**（`src/providers/registry.json`，实测 75 个）。
   `parseProviderModelId` 用 `BY_ID.has(providerId)` 校验，未知 id 直接判死。
   → 面板新增模型时必须校验 providerId，或引导用户从 registry 选；
   不能像现在这样让用户随便写 `probe/vendor-x`。
2. **baseUrl 不得含 `{...}` 占位符**（`hasPlaceholder`），否则该行不产出。
3. **auth.kind=oauth/adc 的 provider 聚合车道不服务**（`authUsable` 直接 false）。

线协议映射（`CHAT_SUFFIX`）：`openai-chat→/chat/completions`、
`openai-responses→/responses`、`anthropic-messages→/messages`。
面板三种格式都已支持；registry 分布实测
`openai-chat/apiKey=64`、`anthropic-messages/apiKey=3`、
`openai-responses/apiKey=1`、local(auth=none)=3（ollama/lmstudio/llamacpp）。

### 2.3 密钥落盘边界（必须先定策再动手）

现在 `Spec.APIKey` 只在本机 settings 里、API 只回显指纹。接通后它会出现在
**每任务隔离 HOME 的 settings.json**（`runtime/dsh-home/tasks/<id>/our-free-model/`）。
retention 包回收任务目录时会带走它。建议：

- 任务目录里的 settings.json 保持 0600 语义（Windows 上继承 ACL，需实测）；
- 或改成「aggregate 配置只在共享 HOME 写一份，任务 HOME junction 过去」，
  与 profiles 同策略（`linkDir` 已有现成实现）。

## 3. 验证步骤（接通后必须全过）

1. 容器内 mock：`tests/docker/mockofm` 已能当 OpenAI 兼容端点用
   （`/v1/models` + `/v1/chat/completions`，支持 `-key` 鉴权与 down/unauthorized 模式）；
2. 面板加一个 providerId=open_router、baseUrl 指向 mock 的模型，置 `routable:true`；
3. 跑一个任务，断言：
   - mock 的 `/ctl/state` `chatHits >= 1`（**证明请求真打到用户端点**，这是核心判据）；
   - `model-status.jsonl` 该模型有 success；
   - 关掉 mock → 该模型被标 down 并自动切到下一个（故障转移对新车道同样生效）；
4. 反假绿：故意把 providerId 写成 registry 外的值，必须**接通失败并给出明确错误**，
   不得静默回落到免费车道（静默改道是现在最坏的行为，因为用户以为在用自建端点）。

## 4.1 面板渲染补丁规格（给 `web/assets_pool.go`，可直接套用）

数据已在 `d.aggregate`（`/api/pool` 返回），只差一个卡片把它渲染出来。
锚点：`renderOverview` 之后新增一个 `renderAggregate`，并在 `load()` 里调用一次。

```js
// 聚合车道：自填端点能否真被 DSH 调用的对账视图。
// 必须展示 rejections/warnings —— 静默丢配置是本模块最不能犯的错，
// 用户看不到拒绝原因，就会以为「加了端点但没生效」是产品坏了。
const renderAggregate = (d) => {
  const a = d.aggregate || {};
  const el = document.getElementById('poolAggregate');
  if (!el) return;
  if (!a.registryLoaded) {
    el.innerHTML = '<div class="card"><h3>聚合车道</h3><p class="muted">未加载 provider 清单：' + esc(a.error || '未知原因') + '（自填端点暂不可执行）</p></div>';
    return;
  }
  const rows = (a.providers || []).map(p =>
    '<tr><td>' + esc(p.providerId) + '</td><td>' + esc(p.baseUrl) + '</td><td>' + esc(p.format) + '</td>' +
    '<td>' + esc((p.models || []).join(', ')) + '</td><td>' + esc(p.keyHint || (p.hasKey ? '已配置' : '无')) + '</td>' +
    '<td class="muted">' + esc(p.overlayModel || '') + '</td></tr>').join('');
  const rej = (a.rejections || []).map(r => '<li><b>' + esc(r.specId) + '</b>：' + esc(r.reason) + '</li>').join('');
  const wrn = (a.warnings || []).map(w => '<li><b>' + esc(w.specId) + '</b>：' + esc(w.reason) + '</li>').join('');
  el.innerHTML = '<div class="card"><h3>聚合车道 · 自填端点对账</h3>' +
    '<div class="kv"><div class="item"><div class="v">' + (a.enabled ? '可执行' : '暂无可用') + '</div><div class="l">状态（provider 清单 ' + (a.registryCount || 0) + ' 个）</div></div></div>' +
    (rows ? '<table class="pool-table"><thead><tr><th>provider</th><th>BaseURL</th><th>线协议</th><th>模型</th><th>密钥</th><th>overlay id</th></tr></thead><tbody>' + rows + '</tbody></table>' : '') +
    (rej ? '<p class="muted">被拒绝（不会被 DSH 调用）：</p><ul>' + rej + '</ul>' : '') +
    (wrn ? '<p class="muted">需注意：</p><ul>' + wrn + '</ul>' : '') + '</div>';
};
```

配套两行：
1. `pool_page.go` 的 `<body>` 内、模型清单卡片之后插 `<div id="poolAggregate"></div>`；
2. `load()` 里 `renderOverview(d)` 之后加 `renderAggregate(d)`。

验收判据（别只看"页面有这一块"）：
- 加一个 `providerId` 不在 registry 的端点 → 页面必须出现该条**拒绝原因文字**；
- 加一个合法端点 → 出现 provider 行，且密钥列显示 `…后四位` 而非明文；
- 断言方式沿用 `pool_api_test.go` 的路子：抓 `/modelpool` 的 HTML 与 `assets/pool.js`，
  检查 JS 里含 `renderAggregate` 与 `rejection` 字样（防"数据面有、界面面没有"）。

## 5. 实测踩到的四个坑（接线前请读完）

1. **候选判据不能只看车道**。第一版 `aggregateCandidate` 的 default 分支看 `Routable`，
   于是 OFM 同步进来的免费/Kilo/EAC 模型（带网关 BaseURL 8326 且 Routable=true）
   被当成用户自填端点，按 `provider/model` 拆出 cohere/poolside 等 id 投影进 aggregate，
   **并把网关密钥写进那份配置**。一旦接线，这些模型会从免费车道改道成
   「用网关密钥打网关的 aggregate 路由」—— 既绕过车道隔离又外溢凭据。
   真实账本实测：22 条伪拒绝 + 2 个被污染的 provider 条目。
2. **`lane=aggregate` ≠ 用户自填**。网关专属车道 `deepseek-official/*` 同步时也落在
   aggregate 车道，但它是 `source=gateway-sync` 的机器清单产物。当候选处理会
   每次面板刷新刷出「providerId 不在 registry」的噪声拒绝。判据必须是
   **车道 ∈ {custom, aggregate} 且 来源 ∈ {user, panel, 空}** 两条一起看。
3. **线协议由 registry 决定，不由用户填的 format 决定**（OFM `entryOf` 只取
   `provider.format`）。填错不报错、只会走成另一条线 —— 所以做成 Warning 上报，
   而不是当校验失败。
4. **密钥会随任务目录扩散**。接线后 BaseURL/APIKey 要写进
   `runtime/dsh-home/tasks/<id>/our-free-model/settings.json`，而 retention 包会回收
   任务目录。两个选项：(a) 实测任务目录 ACL 是否 0600 语义；(b) 像 profiles 那样
   在共享 HOME 写一份、任务 HOME 用 `linkDir` junction 过去（推荐，现成实现）。
   这一条不先定就不要接线，否则是把密钥写进一个会被批量回收的目录树。
