# 缺陷「显示运行中但显示产出为 0」——根因链与修复（2026-10-21）

> 老大原话：**「显示运行中但显示产出为 0」**（面板：引擎 运行中 ｜ 排队 0 ｜ 今日产出 0）
> 当轮追加指令：**「不要给我跳出来窗口，无头执行」**
> 本文只写可复算的事实，所有数字都能用文末命令重新得到。

## 零、结论先说

这个症状**不是单一缺陷**，而是**四层缺陷叠加 + 两层通道拒绝**（一层本机配置、一层外部约束）。

| # | 层 | 缺陷 | 后果 |
|---|---|---|---|
| 1 | 规划器 | 目标标题代际复利增长（每代追加「 · 深化：X」） | 标题被顶到 31 rune / 78 字节 |
| 2 | 截断 | `model.Truncate` 按**字节**、常量叫 `MaxTitleRunes` 按 **rune** | 刚追加的阶段后缀被整体吃掉 ⇒ 每轮产出逐字相同的标题 |
| 3 | 评估器 | `novelty()` 对同目标不做区分（而 `gates()` 早已豁免同目标） | novelty=0 ⇒ 综合分 48 < 55 ⇒ **恒不通过** |
| 4 | 配额 | `tasksToday()` 把 rejected 草案也算进 dailyCap | 2000 条从未执行的草案吃满配额 ⇒ **整天停机** |
| 5 | 通道·本机 | DSH profile 写死 `reasoningEffort: high`；`exit_plan_mode` 在非计划模式仍注册 | 每轮被拒 ⇒ 任务永远跑不完（`bad_exit`） |
| 6 | 通道·外部 | 上游匿名出口池配额（`no eligible anonymous exit`） | 在跑但拿不到产出（**不可代码修复，已做成自证**） |

## 一、现场事实（先取证）

从 `dist/workbench-output/` 的持久化台账直接读出：

| 观测 | 读数 |
|---|---|
| 面板 phase | `running` |
| 今日产出 todayDone | **0** |
| 排队 / 执行中 | 0 / 0 |
| 今日新建任务 | **2000 条，全部 rejected** |
| 今日**唯一**标题数 | **1**（2000 条逐字相同） |
| 今日**唯一** Prompt 数 | **1** |
| 时间分布 | 00:00:02 → 01:39:59，此后当天再无新任务 |
| 决策台账 | 5724 条（plan 5638 / accept 52） |
| 拒绝原因 | 综合分 48.0 / 54.0 < 阈值 55 |
| 得分明细 | `价值先验 60 × 新颖度 0 × 链收益 50` |

## 二、根因链

### 层 1-2：标题被字节截断吃掉阶段后缀

```
78 字节（目标标题）+ " · 阶段6"（11 字节）= 89 字节
→ Truncate 截到 80 字节 → 回退合法 UTF-8 边界 → 正好停在 78 字节
→ " · 阶段6" 被整体吃掉，标题退化成目标标题本身
```

**变异验证**：把 `composeTitle` 换回旧写法 ⇒
`TestLadderTitleKeepsFocusForLongGoal` 判红：`标题退化成目标标题本身（阶段信息丢失）`。

### 层 3：新颖度把同目标合法任务判死

```
价值 V = 60×0.6 + novelty(0)×0.3 + chain(50)×0.1 = 41
综合  = 0.5×41 + 0.2×(100-60) + 0.3×65 = 48 < 55   ← 恒不通过
```

`gates()` 里早有「同目标豁免」且注释在册，但 `novelty()` 没跟上 ——
同一语义两处实现不一致，豁免被新颖度项目抵消，等于没修。

**变异验证**：去掉 novelty 的同目标豁免 ⇒ 判红：`价值分被新颖度判死：value=47.4`。

### 层 4：被拒草案吃满每日配额

2000 条 rejected 吃满 dailyCap=2000 后，两条供货链**同时**停机一整天：

```
supplyAutonomous 在规划前 return false（每日上限是终止条件）
supplyCandidates 的 daily 判据同样命中 → return
⇒ 全天零任务、零产出，而面板仍显示"运行中"
```

**变异验证**：恢复"计入 rejected" ⇒ 判红：`被拒草案不得计入当日工作量：期望 0，实际 30`。

### 层 5：DSH 通道的两处本机配置拒绝（本轮新发现）

现场 `events.jsonl` 逐条可查：

```json
{"kind":"error","error":{"message":"provider \"our-free-model\" model
 \"combo:auto-main\" does not support reasoning effort \"high\"",
 "code":"UNSUPPORTED_REASONING_EFFORT"}}

{"kind":"error","error":{"message":"no eligible anonymous exit; retry after cooldown",
 "code":"EAC_UPSTREAM_FAILED"}}
```

- `reasoningEffort`：`modelOverlay()` 无条件写死 `high`，而池里多个免费/组合车道
  不支持该字段 ⇒ 换模型也救不了（每个都被同一行配置拒）。
  已修：默认不写，需要时经 `modelOverlayWithEffort` 显式传。
- `exit_plan_mode`：该工具在**非**计划模式下仍保持注册（DSH 为请求 cache 稳定刻意如此），
  但它的使用约束只在计划模式激活时才进 prompt ⇒ 小模型把它当成"提交成果"的通用出口
  反复调用（现场同一任务 4~8 次），每次被拒，最后 `bad_exit`。
  已修：profile 补丁禁用 `plan-mode`。

### 层 6：上游匿名出口池（外部约束）

直接探网关 6/6 成功（HTTP 200），但 DSH 插件通道报
`no eligible anonymous exit; retry after cooldown` ⇒ 确认是**上游账号池层面**的限流，
不是本机代码。代码改不动，已做成 `upstream_rejecting` 自证。
