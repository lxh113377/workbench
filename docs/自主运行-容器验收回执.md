## 0. 为什么用容器 + 确定性通道

宿主模型通道受出口 IP 影响会 429/401 波动（本会话已多次实测），
导致「目标完成 → 自动推导下一目标」永远拿不到运行时证据。
容器内把通道换成**确定性替身**（`fakedsh`）后，被测的是工作台自己的逻辑：

```
项目目标 → 动态规划阶段任务 → 执行 → 产物落盘 → 真实执行验收
        ↑                                            ↓
        └── 自动推导下一目标 ← 目标完成 ← 自主验收记账 ┘
```

## 5. 边界与风险机制的容器内实证

- **低质回退**：首版替身未分流时实测 `rollback`「自评 0/10 < 下限 1」，即"低质不计入进度"真实触发过；
- **预算/空转阻塞**：同轮实测 `block`「quality.belowMin, loop.duplicated, budget.stagesExhausted」；
- **产物协议 + 真实验收**：分流后 `c-verified` 通过，未触发能力缺口降级。

### 5.1 替身保真度两个坑（已修，供后续复用）

1. **必须按提示词分流**：工作台除任务本身，还会用同一执行器跑三类语义子任务
   （价值判分 / 自评 / 摘要）。若都回同一段产物块，`parseCritique` 会抓到 manifest JSON，
   `quality` 恒 0 ⇒ 每阶段回退（实测 `plan=14 rollback=7 accept=0`）。
   修法：含「成果评审员」回评审 JSON、含「任务价值评估器」回数组、含「总结」回摘要、其余回产物块。
2. **替身注册方式**：执行器**先**调 `dshprofile.LocateDSH()`，失败即返回，配置 `dshExe` 轮不到生效。
   正解：设 `DSH_DESKTOP_EXE` 指向替身，并让 `<exe 同级>/resources/app/lib/desktop-cli.js` 真实存在。

## 6. 与宿主轮次的口径关系

| 项 | 宿主（本会话早前） | 容器（本轮） |
|---|---|---|
| 通道 | 真实 OFM，429/401 波动 | 确定性替身，零波动 |
| 闭环终点 | 未取得（通道阻断） | **已取得：goalDone=1 / nextGoal=1** |
| 可复跑 | 依赖外部通道可用性 | 一条 docker 命令，离线可复跑 |

两者走同一份代码路径；容器补上了宿主拿不到的那段运行时证据。
宿主轮次"通道是外部缺口"的结论不变，只是把该缺口从验证路径中移除了。
