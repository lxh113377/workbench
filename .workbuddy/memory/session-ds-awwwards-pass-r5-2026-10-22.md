## 本轮主线：把「读数可扫性」从展示层追到数据源头
上轮修了治理台「量化指标」卡（展示层 govNum）。本轮目检那张拍而未看的截图时，
发现同一页下方「风险预警」卡仍是旧格式 —— 因为它的 Detail 文案由
gov.VolumeAlerts 在数据源头用 fmt.Sprintf 拼数字，展示层根本修不到它。

教训（可复用）：修「读数不可读」这类问题，必须先问「这个字符串是谁拼的」。
只在展示层修 = 只覆盖了「走 API 拿结构化数据、自己渲染」的那些卡；服务端拼好的
字符串会带着原缺陷继续显示，于是出现「同一页两种格式」这种更糟的状态（比全旧更难查）。

第 5 条是顺带抓到的真 bug，不在本轮计划内：由 metric_text_test.go 的千分位用例
（-1234.5 期望 -1,234.5）抓到。影响面确认过 —— 本包 pearson() 返回相关系数、
取值域是 -1 到 +1，负相关是真正常态，面板「负载×耗时相关」直接显示它，所以不是理论问题。

## 判据与证伪（本轮 5 条新判据 + 2 变异体）
- gov/metric_text_test.go：numberText 千分位 / percentText 量级 / metricValueText 吞单位 /
  usagePhrase 方向语义 / Detail 不重复 Title（含反向断言：低方向不得出现 400%、
  Detail 不得含指标名、红线为 0 时不得算出 Inf/NaN）
- 变异验证：M-A 退回带指标名前缀 → CAUGHT；M-B 比例退回裸小数+单位粘连 → CAUGHT

  补长小数 MemMB 后才 CAUGHT。这条写进测试注释：判据样本必须能让回归可见，否则 PASS 是假绿。

## 踩坑（新增）
1. 在 run_code 的 JS 字符串里写含裸双引号的中文文案会提前闭合字符串（本轮两次）；
   正解 = 用全角引号或书名号承载，别在双引号串里嵌半角双引号。
2. 探针脚本里内联 JS 表达式经多层转义后，正则与文件名会被吃掉：
   反斜杠 d 变控制字符、文件名里的反斜杠 a 变成 BEL，截图写进不存在的名字（目录空）。
   正解 = 文件名用 path.join 拼、表达式内只用单引号、中文关键词走 unicode 转义。
3. spawnSync 跑 go test 有时拿不到 stdout（同一命令在 pwsh 里有输出）：
   别把「输出为空」读成「测试没跑/失败」，改用 pwsh 复核。
4. gofmt -w 会连带修掉既有漂移：alerts.go 在 HEAD 即不合规（10 行对齐），
   我编辑的那两个函数被一起规整（+4 行，可接受）；但 volume.go 有 92 行漂移，
   不顺手改（scope creep 会撞并发会话）。判据：改前用 git cat-file 取 HEAD blob
   单独 gofmt -l，区分「我引入的」与「既有的」。
5. CI 无 gofmt 门禁（.github/workflows/ci.yml 只有 check_changelog /
   check_noninteractive / issue forms），所以仓库里存在长期格式漂移。
